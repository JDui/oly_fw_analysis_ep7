# EP7HSL 020 / 1.1v020 — COLOR HDR 处理分支修正

2026-11-08，E-P7 原厂 1.1 / build 1100。

用户确认 019 已可调节等级，但 COLOR 1 的取景和 JPEG 均看不出 HDR 效果；原有
高光／阴影和 Midtone 调整正常。用户随后明确：只需支持 COLOR。

020 仅对 **COLOR 1–4** 启用高光映射。其余模式不应用映射；
若从普通曲线入口进入 HDR 页，非 OFF 选择显示 N/A。机身版本为 **1.1v020**。

说明更正：COLOR 下没有让用户手动选择“灰阶标准”的入口。先前将内部处理条件
写成菜单操作是错误的；用户无需设置灰阶。固件仍检查实际处理请求的兼容性，若内部
字段被拒绝，由处理状态反馈排查，不能要求用户寻找不存在的菜单。

## 修正内容

原厂存在复用颜色表的普通处理分支。019 遇到这个分支就跳过 HDR，尽管原厂选出的
RGB 曲线是已支持的类型。相同分支在 019 原生指令回放中复现失败，020 对已知曲线
可以正确选择 HDR 表；未知表和不兼容条件继续保持原厂处理。复用的原厂表本身不改写。

本轮保留 019 的曲线强度、原 COLOR 参数传递及曝光／ISO／采集增益。当前 400 的
三张曲线最大改变量仅为 12-bit 输出 61／72／153 码，约满量程 1.5%／1.8%／3.7%；
这说明强度偏保守，但不能据此证明实机已应用映射或计算实际 JPEG 差异。

## 安装及一次实机确认

1. 将 `install/DCOLYMP` 放到 SD 卡根目录，按此前方式更新，版本页确认 `1.1v020`。
2. 使用 COLOR 1；INFO 切到 HDR 页，选 400，无需调整灰阶。
3. 退出曲线页，拍一张新 JPEG，再回到 HDR 页，读取末尾 `Vxx Pxx`，不要先转拨轮。
   例如 `HDR OFF 200 [400] V42 P42`。将两组状态反馈给本对话。

`V` 是取景处理，`P` 是拍摄处理。`41` / `42` 表示对应路径的 RGB 配置已经选择
HDR200 / HDR400 表，**不表示已经验证硬件上传或真实 JPEG 像素效果**。画面重新
绘制时读取状态，没有新增定时刷新；切换 HDR 档位或长按 OK 复位会清除观测记录。
刚转拨轮显示 00 是正常的，退出、拍摄后再进入才能读到后续处理结果。

| 状态 | 最近观察到的阶段 |
| --- | --- |
| 00 | 清除后尚无观测 |
| 10 / 11 / 12 | 源快照读到 OFF / 200 / 400，尚无后续观测 |
| 20 / 21 / 22 | job 收到 OFF / 200 / 400，尚无 RGB 结果 |
| 41 / 42 | RGB 配置选中 HDR200 / HDR400 表 |
| 50 | 源快照读取设置时被忙碌／队列守卫阻断 |
| 60 | 源 owner 或模式不属于支持的 COLOR 路径 |
| 90 | RGB 请求的模式／类型／来源不兼容 |
| A0 | 内部 RGB 请求携带尚未支持的灰阶标志；不是要求在 COLOR 菜单改灰阶 |
| A1 | RGB 请求包含未支持的特殊处理标志 |
| B0 / B1 | RGB 三通道表不一致／原厂表不在已支持列表 |
| D0 | 到达 RGB 配置时 job 等级为 OFF 或无效 |

观测只读处理状态，不决定渲染。不同原生帧可能交错，且所显示的是最近观测，不是
逐张完成凭据；仍需结合选择档位及新拍摄结果判断。

原厂恢复文件为 `restore-stock/DCOLYMP/E1429999.BIN`。安装和恢复目录不要同时
合并到 SD 卡；恢复依赖相机更新入口仍可用。

## 验证边界

同一候选的原生普通／复用表 RGB 选择、缓存、取景与拍摄等级传递、未知复用表回退、
原 HSL 数据、CPU 0/1 INFO／双拨轮和状态文本通过定向回放。原厂属性通知、原生
job/RAM、跨核调度及设备存储仍有明确模拟边界。封装流程核对最终镜像等于测试候选，
执行既有原厂加载、五组件回读、升级路由拦截及 ZIP 回读，不执行 SHA 或相机写入。

未声称 COLOR 1 实机一定走上述复用分支，也未完成 020 实机显示、JPEG 效果或
关机保存验收。若两组均为 42 但效果仍弱，下一步才根据实际照片调整映射强度。
