## 已选定的承载格式与实施顺序

复用上一节点的`ep7t_ticket`，在独立拥有的消息缓冲中编码：

- 原生16字节command或300字节descriptor前缀完整保留。
- 尾部12字节为4字节版本标记和little-endian 64-bit serial。
- metadata身份从原生command+12 / descriptor+48获取并与票据匹配，不再重复编码地址。
- 结果为28字节command、312字节descriptor。旧16/300消息没有票据，保持中性。
- 接收必须取得raw实际长度并先写入足够大的独立缓冲；不能在stock栈上读写额外12字节。
  拷回stock前缀，票据存入与该次调用/消息同寿命的独立上下文。不得以当前裸地址重建。
- 每次新接收先清旧上下文，失败保持无票据；换到备用queue4d也要清理。
  只在成功接收且长度/版本/身份一致时传递票据；不支持的路线转为中性。

command最大148已足够容纳28。三个descriptor队列则需要最大300→312，并把各自
ring9728→10112，以保留32条“最大长度+4字节记录头”的缓冲预算，共增加1152字节。
这不是对实际在途消息数的承诺；混合短消息、等待线程、调度及内存预算另行审查。
队列配置、全部可能接收点和shim必须作为一个原子安装集合，不能先启用大消息发送。
