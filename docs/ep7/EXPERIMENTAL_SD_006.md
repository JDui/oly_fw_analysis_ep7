不要重复刷006。使用此前成功的原厂回刷路线恢复，详见[事件记录](BOOT_FAILURE_005.md)。

目标：E-P7 原厂 1.1 / build1100。保留色轮编辑、四个 COLOR profile 的易失 H/L
及 CPU 照片处理。006 修正一个已离线复现的未接管阶段误停机，并增加故障指示；
**还没有证明它解决了005的实机黑屏，也没有完成006的真机开机验收。**

## 改动与判断依据

- 拍摄扩展尚未选择所属任务时，其他原厂任务进入清理观察钩子，现在保持原厂行为。
  005在此条件下会进入`0xe03`永久停机。已接管后的异任务破坏性回调仍被阻止。
  离线反例没有证明相机本次启动真的走了这一调用，不能作为唯一根因结论。
- 遇到扩展终止条件时记录首个错误码，并尝试调用原厂 E-P7 更新器使用的 AF/PWM
  函数（通道0、250ms参数），随后保持终止状态。没有用未知 GPIO 地址自行驱动灯。
  此提示依赖原厂时钟/PWM服务；实机可见性尚未验证，灯不亮也不能排除扩展终止。
- 封装继续复用 fishcu 的 `parse → replace_payload → reconstruct`；五组件、型号、
  版本字段保留，原厂启动前缀和 CPU2 的32槽池保持相同。不做SHA校验。

## 006首次测试

1. 当前原厂能正常开机时，先拍基线照片并备份卡上照片，充满电、断开USB、关机。
   保留本次报告的 **A档、前拨杆COLOR** 条件，以便判断同一触发条件是否仍失败；
   记录当前 COLOR profile。
2. 使用 `install` 中的文件，确认卡根目录为 `DCOLYMP/E1429999.BIN`。
   关机插卡，按住OK开机，更新指示开始后松开。
3. **更新过程先常亮、完成后快闪**。常亮时保持供电；确认转为完成快闪后拨OFF。
   完成快闪可以持续，不以“自己停止闪烁”作为完成条件。
4. 关机后取出更新卡，换没有更新文件的卡，不按OK正常开机。
   观察画面、菜单、回放，以及AF灯是否有持续闪烁。
5. 若普通开机仍黑屏，记录有无AF闪烁及大致节奏，停止重复刷006，按此前成功路线
   使用 `restore-stock` 回原厂。**普通开机的故障闪烁不是刷写完成指示**：必须结合
   是否处于OK更新流程、卡上是否有更新文件判断。

SD流程沿用[fishcu安装说明](https://github.com/fishcu/oly_fw_analysis/blob/alpha-20261017/releases/alpha-20261017/INSTALLATION.md)，
并结合本机005更新/原厂恢复的用户报告；不是 E-P7 官方恢复保证。

## 开机成功后验证功能

先检查菜单、普通拍摄、JPEG写卡与回放。再进入COLOR原有色轮编辑界面，用原厂类别
切换控件寻找H/L，检查单个扇区增减及文本显示；不要套用PEN-F的Delete切轴操作。
四个COLOR profile分别检查，退出重进后当前开机周期内的值应保留，重启应归零。

照片比较先固定曝光、白平衡、机位和场景，分别拍零值、仅H变化、仅L变化三张JPEG。
尽量先用小幅单扇区调整，确认可回放、颜色/明度变化符合所选扇区。色轮可编辑不等于
照片处理已经生效；需要两项分别验收。原厂版本显示仍可能为1.1。

离线验证覆盖实际候选指令的任务准入、原厂AF调用参数、GUI编辑/冻结、worker系数
及容器/更新路由。GUI构图、显示和处理服务仍包含明确模型边界；没有完整相机模拟、
物理擦写回读、缓存/多核时序、全模式画质或独立恢复验收。

本轮对006执行fishcu全组件解码/加和校验和原生mode1写入路由、错误停止；没有重跑
耗时的全包原生mode2解码，包内记录明确标为false，没有沿用005的结果冒充006通过。
