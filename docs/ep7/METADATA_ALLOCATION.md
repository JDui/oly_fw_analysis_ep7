## Proposed owned-allocation order

For the qualified local controller route, capture immutable sidecar state into wrapper-owned temporary storage after membership-before-dereference and reciprocal association/ID checks, before nested calls can clobber inputs; alternatively preserve all necessary inputs and prove their lifetime across the allocator. Request192 explicitly from the original allocator, not148 followed by a tail read. Preserve native148 prefix semantics. On successful actual192 allocation initialize the complete44-byte extension neutral, then seal only an independently qualified copied snapshot. Other producer returnPCs remain neutral without dereferencing their unqualified a2. Allocation failure must never access prefix/tail; the native c753/c754 sequence itself has no null check, so an installable wrapper needs a separately reviewed failure policy consistent with allocator contract, not an invented safe fallback.

# Downstream extent admission is separate from allocation-wrapper feasibility

The34-witness allocation probe proves a concrete c748 seam, NOT that every kind19/dispatch0x2001 metadata pointer originated at that seam. Enlarging every c748 invocation to192 establishes extent only for actual successful allocations through that wrapper. ReturnPC admission distinguishes the two observed direct producers at allocation time; its evidence is not carried automatically by kind19, command0x2001, pointer equality, captureID, a magic word, or a copied generation tag.

A downstream reader MUST NOT read metadata+148 or any proposed trailer field merely to decide whether that trailer exists. Kind19's routing row603dfbcb and dispatch selection accept incoming command metadata; they do not check its allocator origin. Existing bounded route explicitly branches on other command values such as2008, so kind19 alone is not even exclusive to the audited2001 branch. Neither the route nor the two direct c748-call candidate inventory enumerates all command senders, indirect producers, injection contexts, or allocation lengths accepted by that generic routing machinery. No all-kind19/all-2001 producer closure is claimed here.

Two possible future admission designs, neither supplied by the allocation probe:
1. An independently synchronized owned-metadata allocation registry qualifies the exact live pointer and192-byte extent BEFORE any tail access, registers only after a successful explicit192 allocation, revokes before every supported free/reuse, and supplies allocation-generation capability to the consuming route. A registry keyed only by current address still cannot distinguish an old queued pointer from a new allocation reusing that address; retain the native no-stale-descriptor/lifetime contract or explicitly owned generation-bearing handoff.
2. An exact independently qualified producer-to-consumer capability handoff proves provenance and live extent without using untrusted tail inspection. Merely asserting the packet haskind19/2001 is not this handoff. Compiler-only adapters may expose unresolved admission functions, but must not implement those functions as a magic/tag check.

Local prefix observation remains bounded: in c748..c870 direct native metadata stores use fixed offsets through104(2bytes) and the a2=metadata+84 alias; cf12 only computes scalar d0/d1; command publication passes metadata pointer, not an explicit148-byte copy. Existing route evidence pins pointer transport, including metadata pointer into descriptor, rather than showing an unconditional148-byte-copy truncation. This does not prove all downstream writers/copies preserve extension, nor relieve extent admission before reading it.

Thus a compile-only allocation adapter can preserve148 prefix and initialize an explicitly owned44-byte tail while downstream consumer integration remains blocked on independent extent/lifetime admission. On any missing qualification, leave H/L neutral without inspecting an unqualified trailer. Native sidecar for56-byte nodes and owned metadata membership are different lifetimes and must not be conflated.
