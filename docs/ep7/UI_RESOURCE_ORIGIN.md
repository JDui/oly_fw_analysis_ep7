# UI 初始化数据搬运与文本资源来源

本次将启动数据段的原生读取参数连接到两个既有 RAM 表，并找到四个可继续研究的
原厂文本模板。没有重造资源、填写全零描述符或挪用现有控件。这里验证的是条件成立
时的静态搬运关系，未运行整机启动、NAND/ECC、缓存同步或实际字形渲染。

## 启动读取范围

`600201ab..600201b1` 将结束地址 `6025eb50` 保存至 `6218d984`。
`600201fe..60020216` 随后构造调用 `6002144e`：

|项目|值|
|---|---|
|逻辑 flash 来源 A0|`408b0800`|
|目标 A1|`a1f98540`|
|长度 D0|`6025eb50 - 60230800 = 189264`（`2e350`）|
|主组件 payload 逻辑 flash 基址|`406a0020`（头地址 `406a0000` 加 32）|
|对应解码镜像区间|`60230800..6025eb50`|
|按现有 RAM 地址别名关系对应的 cached 区间|`61f98540..61fc6890`|

`6002144e` 保存三个参数；该长度小于 262144 且来源按 2048 对齐，走
`600215b4` 的整页读取和尾部复制。整页部分 188416 字节，尾部 848 字节；
尾部通过 2048 字节临时读取后复制准确剩余长度。来源减去主组件 payload 基址
与对应解码镜像偏移完全一致。原厂 source helper `60021279` 对 `40000000`
来源范围做减基址和 2048 对齐检查。

RAM 的 `a1/61` 别名按既有固件分析采用的地址映射解释；本批没有把这项静态关系
扩写成硬件 cache 一致性、启动读取必然成功或所有后续写入均已排除。

## 两个表的对应关系

- `61fb7070` 的 58 个资源指针对应镜像 `6024f330`。下标 0 为 NULL；原厂
  `60d7ac19..60d7ac2a` 取该表，读取描述符 type，再传给通用 widget factory。
- `61fc3874` 的 7 个父控制器回调对应镜像 `6025bb34`，值依次为
  `60e261f0 / 60e26215 / 60e26270 / 60e262c0 / 60e26397 / 60e2642a / 60e26609`。

这解决了此前“只见 RAM 消费者、不知初始数据来源”的具体缺口。实际安装仍应在
合适生命周期核对当前表项，不能由初值推断它们一直未被替换。

resource string ID=0、flags=9，descriptor+68/+84 均为 0，符合现有 fresh rollback
的两个父指针访问保护条件。两个 style 变体沿用原厂记录；这里未生成可部署副本。

`service virtual+692/+696` 的实际函数分别为 `60d01efa/60d01f01`，返回 service
半字 +82 的当前 index、+80 的 count，且会符号扩展。原厂 initializer 按 count*8
分配/复制，并按 index*8 取布局。新模板接入必须核对 count=2 且 index 为 0 或 1，
在整个创建期间保持服务布局状态稳定；不能只检查 layout 指针非空。

descriptor+12 指向 `610308ec / 6103090c / 61030a4c / 61030a5c`，每处已审读
四个零 word。该字段会原样复制到 object+24；其语义仍未完全核实，不能据此直接换成
NULL、借用短期栈数据或宣布可无条件克隆。descriptor+56 的实际值均为 7，也不能凭
字段宽度把它称为指针。字体 1 的原厂使用是有依据的参考，H/L/ALL/MIX 的实际字形、
专有布局与焦点/父容器所有权仍需继续完成。

核对 71 条指令、服务的两个 vtable 项、四个描述符的关键字段、两组布局和 callback 表。

下一项复用原厂工厂，但通过 GCC veneer 同时带回 A0=child 和 D0=初始化状态，
并保存/恢复全局 allocator context。非空 child 不等于初始化成功；失败的新对象必须
走已审查的 cleanup/destructor/deallocator 路线。之后才能接实际 parent attach、
新 category4/5 的显示资源与 ready 准入。
