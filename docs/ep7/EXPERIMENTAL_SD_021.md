# EP7HSL 021 / 1.1v021 — COLOR 高光映射与请求兼容修正

2026-11-08，E-P7 原厂 1.1 / build 1100。支持 COLOR 1–4。

用户在 020 返回 `V42 P90`，实时取景和 JPEG 仍没有明显效果。V42 只证明最近的
取景 RGB 配置选中了 HDR400；P90 是拍摄请求的模式、类型或来源三个判断共用的
拒绝码，不能据此确定具体字段，也不是整张照片所有处理阶段的完成凭据。

## 本版改动

1. 补上原厂同一 COLOR 流程支持的请求类型 16。020 只接受类型 0，遗漏了这个
   合法分支。原厂分发指令及 021 实际 RGB 选择、缓存回放均已核对；没有把类型 3
   等后续格式转换阶段一并放开。实机 P90 是否来自类型 16，仍需新状态确认。
2. 加强高光肩部，200 为温和档，400 为完整强度。三组 400 LUT 的最大压缩量从
   153／61／72 增至 687／279／235 个 12-bit 输出码，约原来的 4.5／4.6／3.3 倍。
   这是曲线数学差值，不是 JPEG 动态范围倍数，也不能换算成实测 EV。
3. 将笼统的 90 拆成具体字段诊断，版本显示同步为 `1.1v021`。

新曲线逐字保留节点 0–48，0 与 4095 两端不变，单调、不增亮，且只在最后一个
节点到达纯白。200 在原厂与新肩部之间作等权混合。保持曝光、ISO 和采集增益，
作用于 RGB LUT；传感器或其他前级已经裁掉的细节无法靠这张曲线恢复。

## 安装及对照

1. 将 `install/DCOLYMP` 放到 SD 卡根目录，按此前方式更新，确认版本 `1.1v021`。
2. 使用 COLOR 1，对同一有高光纹理的静止场景，在相同曝光和白平衡下分别拍
   OFF、200、400 的新 JPEG。COLOR 无需也没有要手动设置的“灰阶标准”菜单。
3. 选 400 后退出曲线页，拍摄，再回到 HDR 页读取 `Vxx Pxx`。读取前不要转拨轮，
   因为切档会清除观测。若仍看不出差异，反馈这两组码，保留 OFF/400 原 JPEG 供比较。

取景状态为 V，拍摄状态为 P。41／42 只代表 RGB 配置选表；不同原生帧可能交错，
显示的是最近观测，不代表硬件上传、JPEG 编码或逐张像素验收完成。

| 状态 | 含义 |
| --- | --- |
| 00 | 切档清除后尚无观测 |
| 10 / 11 / 12 | 源快照为 OFF / 200 / 400，尚无后续观测 |
| 20 / 21 / 22 | job 收到 OFF / 200 / 400，尚无 RGB 结果 |
| 41 / 42 | RGB 配置选择 HDR200 / HDR400 表 |
| 50 | 设置快照遇到忙碌或待处理队列 |
| 60 | 源 owner 或模式不在支持的 COLOR 路径 |
| 91 | 实际 RGB 请求的模式键不是支持的 COLOR 键 |
| E0–EF | 请求类型不支持；后一位为十六进制类型值，15 及以上显示 F，例如 E3 为类型 3 |
| F0–FF | 输入来源不支持；后一位为十六进制来源值，15 及以上显示 F，例如 F3 为来源 3 |
| A0 | 内部请求的 Gradation 标志不兼容；由固件侧排查，不是要求用户改 COLOR 菜单 |
| A1 | 未支持的特殊处理标志 |
| B0 / B1 | RGB 三通道表不同／原表不在已支持列表 |
| D0 | RGB 配置时 job 等级为 OFF 或无效 |

INFO 三页轮换、两个拨轮和长 OK 复位沿用已修复的操作。非 COLOR 模式维持原厂
渲染，非 OFF 选择显示 N/A。原厂恢复文件在 `restore-stock/DCOLYMP/E1429999.BIN`；
安装和恢复目录不要同时合并到 SD 卡，恢复依赖相机更新入口可用。

## 验证边界

同一候选通过类型 0/16 的原厂分发、类型 16 的实际 RGB builder、复用表选择、
不支持请求回退、等级传递、OFF、缓存、设置、CPU 0/1 UI 和版本文字定向回放。
新增原厂上传函数 `60346e37` 的完整执行：对两个以 RAM 建模的 MMIO 表区核对
256 个值，并检查缓存复用跳过及切档更新；两次互斥服务调用为明确的模拟边界。
这证明该输入下 CPU 会写出所选曲线，不证明真实 ISP 已启用或真实照片改善。

交付工具继续核对最终镜像与已测候选逐字节一致，检查既有加载器、两份 ELF 叠加、
五组件加和、升级写入路由拦截和 ZIP 回读。没有 SHA、相机写入或物理 JPEG 验收。
