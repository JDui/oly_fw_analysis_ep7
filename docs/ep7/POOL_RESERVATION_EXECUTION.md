# Domain2 大块池：保留边界的原生执行

复用[严格 GNU 引擎](STRICT_SIM_ENGINE.md)，在显式内存现场中执行 E-P7 原厂
分配、释放、位图和 PSW helper。没有重新实现分配器，也没有为原厂服务返回伪造成功。
仅在模拟器的代码缓冲区把两处槽数立即数从32改为31；原厂输入、解码文件和升级包均未改写。

## 结论

缩容后的**新分配**和**释放上界**按预期排除槽31，即拟保留的
`61dd4d00..61dd8d00` payload。但回收路径从回收栈取出槽号后，没有再与新上界比较。
如果旧状态中已有槽31，缩容后仍会返回 `61dd4d00`。因此，该方案必须在首次原厂分配前
随启动前缀生效；不能靠后来修改两个立即数取得这16 KiB，也不能擅自清空仍有所有者的池状态。

这是一条可重现的晚安装反例，不是原厂正常冷启动会产生错误状态的证据。
启动前缀上游加载、计数器/回收栈的真实初始化、其他访问者和整机容量尚未闭合，
`approved_for_placement` 仍为 false。

## 最小执行范围

[探针](../../tools/ep7_pool_reservation_probe.py)复用96条精确指令检查和原厂stride/回收表，
7次短调用经过250个不同原厂地址。每个状态转换都比较完整的840字节控制区；
payload与guard不映射，执行期间若读写它们会立即停止。

|现场|实际结果|
|---|---|
|原厂32槽，next=31|返回槽31 `61dd4d00`，next变32，bitmap变ffffffff|
|候选31槽，next=30|返回最后保留的槽30 `61dd0cc0`，next变31，bitmap变7fffffff|
|沿用上一现场，再分配|在原厂耗尽诊断入口 `6002247c` 停止，控制区未变|
|释放槽30|bitmap清bit30，回收计数变1，原厂回收栈写入30|
|沿用释放后现场再分配|原厂弹出30并返回 `61dd0cc0`，next仍31，bit30重新置位|
|向候选释放槽31|在非法释放诊断入口 `60022694` 停止，控制区未变|
|回收栈人为保留31|候选仍返回 `61dd4d00`，证实回收槽号未重新检查上界|

控制字来自本输入的实际指令和表：next位于 `62668c08`，回收计数 `62668c14`，
回收半字栈 `62668ed8`，分配位图 `62668f44`。回收路径
`60022a0f..60022a2d` 递减计数、取半字槽号、计算 `base + index * 0x4040`；
其中没有再次读取或比较31槽上界。

CPU ID=2、`8ff006fc=0`、`8ff00040=0` 是显式合成现场；这是原厂锁包装器的
pre-kernel分支。`60054d9f` 把LM降为0，池操作保留该值，正常返回经 `60054dc0`
恢复原IRQ mask，SP和四个callee-saved寄存器恢复。原厂 `udf00`、DIV和位图指令均由
既有GNU模型执行；未增加CPU指令语义。CALL在调用方SP处写4字节返回地址，检查将其
作为调用方已提供的槽，未把它误计为越界。

## 未关闭的条件

- 耗尽与非法释放在诊断**入口前**停止；没有证明诊断会返回、故障策略或调用方容量处理。
- 没有运行调度器激活后的锁分支、IRQ注入、跨核并发或物理cache；没有把LM观察值当硬件互斥验收。
- 未执行启动清零/装载，也未找到guard初始化者。只有上述执行路径的payload/guard未访问结论。
- 未做固件整体编译、相机连接或写入；没有SHA校验。

[结构化结果](../../research/ep7/pool-reservation-probe.json)包含现场、精确状态转换、
停止地址和各次执行步数。此节点细化G6的冷安装必要条件，不放行G8。
