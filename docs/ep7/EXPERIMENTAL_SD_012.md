# EP7HSL 012：轴文字与原生 H/L 图像参数传递

**后续实机结果：用户确认保存的 JPEG 已有正确 H/L 效果。** 实时取景仍只有 Sat 生效，
Hue／Lum 不实时；标题需要半透明底色，切换曲线等页面后有残留。
后续修改见 [013](EXPERIMENTAL_SD_013.md)。以下为 012 当时交付说明。

2026-11-02，E-P7 原厂 1.1 / build1100。

011 的实机反馈已确认：删除键可以切轴，数值及轮廓可以分别调节；顶部有灰黑色背景，
文字需按 OK 退出重进后才出现，切轴时不刷新，底部仍是原厂 `Vivid ±0`。
原有 S 有效果，H/L 的取景画面及保存的 JPEG 没有变化；无论是否 COLOR 模式，
保存图片完成时都会卡死。预设保存目前看正常。011 的离线模拟没有覆盖这些实机结果。

## 操作

1. 进入 COLOR 色轮页，按删除键循环 **S → L → H → S**。
   轴标签使用 **Sat / Lum / Hue**，当前色区位置随切轴保留。
2. 前拨轮选色区、后拨轮改数值，INFO 切换单色区／ALL。
   四个 COLOR 组分别记录 H/L，范围保持 E-P7 原厂图形支持的 **−5～+5**。
3. 每次调节写入原厂设置记录。短按 OK 使用原厂退出行为，
   长按 OK 使用当前轴复位；H/L 的复位值为 0。
4. 重启后默认进入 S。切到 H/L 核对保存值；轴选择本身不跨重启保存。

## 修改与验证范围

012 保留 PEN-F 式同色轮切轴与 H1 设置编码，H/L 存在原厂 ACTIVE 的 part-1 单元，
保存／召回使用原厂设置机制。

轴标题改为透明的 Sat／Lum／Hue，沿用现有原生文本控件的字体与样式。
进入文字绘制前恢复容器的原点／裁剪区域；切轴后通过原生 GUI 根对象标记整页重绘，
避免仅刷新色轮导致旧标题保留。底部 `Vivid ±0` 仍是原厂效果标签，不用它表示当前轴。

图像参数传递改用原生图像快照及每个处理任务的 24 字节 H/L 尾部，
参考 `patches/hsl/pen-f/src/editor_storage/image_transport.s` 的现有方案。
当前任务的参数随图像传递，避免处理时误用后来切换的 COLOR 组。
原生队列、任务和清理路径恢复原厂行为，不再经过原有强制停止保护。
快照覆盖 25 个原生捕获槽和原厂临时克隆，两个转换器分别传入每个 job 的尾部；
构造器分配从 15488 扩为 15512 字节，原厂清零从原尾部 16 扩为 40 字节。
COLOR 参数处理保留原厂 S、控制字及校准字段，仅改 H/L 的两个系数通道。

旧实现仅向 state33 中已注册并符合特定 stage 的拍摄任务传递 H/L，
原生预览及其他处理任务可能被这个门槛中和。012 在原生捕获参数完成后冻结 H/L，
经常规与 CPU2 两个转换器传递，在共同 COLOR builder 之后按实际 job 读取。
这覆盖对应的原生图像参数路径；连续实时取景的实际调度仍须机身确认。

文字与图像处理的定向检查以最终固件包内 `evidence/` 的记录为准。
执行实际文字布局与裁剪到字形提交边界，实际 H1 读取、捕获采样、两条转换、
构造清零、COLOR builder 和两个原厂 MMIO 上传窗口的机器码；
同一捕获槽切到非 COLOR 时验证中和且不读取 H1。
预览请求的覆盖范围、实际执行的原生函数及仍采用模型的后端必须在证据中列明；
仅把字符串传给模拟接口不能证明机身显示成功，仅写出系数也不能证明 JPEG 像素效果。

封装复用既有五组件流程：检查原厂加和校验、字节回读、原生 mode1 更新路由及
ZIP CRC／内容一致性。不做 SHA 校验，不重复完整原生 mode2 解码。
这些检查不代替机身显示、正常关机存储、按快门稳定性与 JPEG 效果验收。
