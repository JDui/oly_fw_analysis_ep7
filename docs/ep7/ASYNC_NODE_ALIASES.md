## 异步描述符并非只有一个无法追踪的裸指针

`602a2f91` 接收 node a1，先检查node+8关联对象的+6为0。
当busy字节6223dd51已经为1时，2fb5直接给node+4置bit4、2fba调用302b，
随后增加6223dd58；这条分支不再提交下面的异步描述符。

另一分支2fce开始置node+46与busy为1，构造全局描述符6223df5c：
类型半字39，+4=回调6029e8f1，+8=node，+12=数据指针6223dee4。
3011以a0=描述符调用6010b2d5。其分发表基址601a9198，按(type-7)*4索引；
第39项地址601a9218实际指向6010b351，再调用6010bf9f。

6010bf9f构造下一层全局请求621d9e64：+4=6010bfe2，+8=原描述符a0；
随后bfd9调用6011209b。低层回调6010bfe2从入参+8恢复上层描述符d3；
c04c..c059检查上层+4非空，以a0=d3间接调用它。因此已接通“原描述符+8节点”
与6029e8f1参数布局，而不只是观察到回调函数地址。

6029e8f1从a0+8读取node到a2，从+12取得辅助数据；部分分支写node内坐标字段。
e93e..e945在node+4置bit4，e947调用602a302b（既有event4c条件发射路径），
然后e94d清busy字节6223dd51。此次选定窗口没有清除描述符+8中的旧node指针。

**尚未证明**：6011209b的入队/复制/调度契约、回调线程/中断域、取消后是否仍回调、
全局请求被其他调用者复用的序列、回调与节点free互斥。这些不能由busy字节自动推出。
仅清busy也不是清除节点别名或所有异步使用者已退出的证明。

## 全局node与wrapper队列

602a3052把当前node保存在6223dd54（3064），然后向6060b54c传递栈上请求，
其中回调为602a309d，后者发送event4e。30af及event4e处理433c继续读取这个全局node。
当前四个字面引用中仅3064是store；这不是对间接store/别名的穷尽证明。

event4e的43db..43f2检查并pop queue6223e2f0；返回值d0作为wrapper保留到a2。
43fb读取wrapper[0]作为node传给3052。4402恢复a0=wrapper，4403调用heap free。
因此**602a4403是新增的wrapper-only free，不是第14个节点free**。
之后440a还可分配新的node，原event4e节点仍保存在a3并在后续独立完成逻辑中处理。

旧清单的13个节点释放点仍非完整生命周期证明。新wrapper-only位点不应误绑
`ep7c_forget`；state33内的真正节点释放、取消、共享全局描述符重用仍是接入前条件。

## 模拟边界：自定义指令槽

低层回调的6010c000和6010c027都被GNU objdump2.45显示为`udf00`。
尝试AM33解码，6010c000仍同样显示。当前源码
`opcodes/m10300-opc.c`将fd000000/maskfffc0000列为udf00立即数形式。
这证明GNU工具对该编码的名称，不解释E-P7硅片语义。不得猜作普通AND、NOP或成功返回；
后续如模拟该回调，必须先建立独立指令语义，或明确停止于该边界。
该问题不影响已经核对的其他地址处寄存器/指针传递指令，但限制整函数执行结论。
