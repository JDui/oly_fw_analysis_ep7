# 冷启动顺序与私有区清零桥候选

2026-10-31。本批把 `600201fe` 接续推进到可汇编、可定向验证的清零桥，补齐三核
冷启动的局部指令顺序。**没有安装跳转、改写镜像、调用候选 C 或发布 runtime。**
代码/RAM放置资格、启动前缀加载及硬件可见性仍是 G6 的独立门槛。

## 原厂冷启动的已核对顺序

主核将 SP 设置为 `470007fc`，跳入 `600200f9`。在早期 kernel 搬运之前，
`60020188/18e/194` 将 `8ff00058/59/5a` 三个字节写零。
`6002067a` 仅在三个字节都等于1时返回1；搬运器两端的 `6002195b/1984` 据此
决定是否调用原生 semaphore 操作。这解释了局部冷启动路径如何跳过这两个锁调用，
没有证明搬运器的全部传递调用、其他写入者和中断闭包。

|局部次序|地址和作用|
|---|---|
|1|`600201f9` 从 flash406b0000 复制 kernel 到 a0030000，长度657,408|
|2|`600201fe` 完整6字节 `mov (6218d984),d0`，拟接清零桥并回到60020204|
|3|后续数据和 helper 搬运、原厂初始化调用|
|4|`6002030e` 清共享启动字 a26c3388|
|5|`60020320/349` 将60027117/60027575写到98d00140/144；相关控制寄存器随后写入|
|6|`60020365` 将D2写到a26c3388；本地前段D2曾设为1，但未穷尽证明所有callee保持它|
|7|`60020392` 调用6003009c，再跳600325ce进入主核kernel启动|

次核一从 `60027117` 转到 `60027209`，读取 `a26c3388` 的循环在 `60027219`；
次核二从 `60027575` 转到 `60027614`，对应循环在 `60027624`。两条路径均在
非零后复制1536个word的helper，随后分别转到 `600325db/600325e9`。
**两条次核路径在等待之前都会调用60054a7a**，所以“有等待循环”不能表述成
“之前完全没有代码运行”。寄存器写入的硬件启动含义、可见性与实际冷复位状态未验证。
后续[等待前调用闭包](SECONDARY_PREBARRIER.md)确认该调用只输出各自的`1`/`2`并可选记录
诊断ring，无allocator调用；诊断关闭的明确现场中，两入口已执行到等待点且未访问堆。
启用诊断时的buffer指针写入仍保留所有权条件，未把该结果提升为全核静止证明。

搬运器 `6002161d/61e` 清D0后按 `[d2,d3,a2,a3],32` 返回；仅观察到调用返回，
不足以确认所有目标字节搬运成功。上述结论均限定在当前输入已核对的局部指令顺序。

## 清零桥的具体契约

[实现](../../prototypes/ep7_volatile_hl/target/cold_clear.s)为21条指令、53字节，无data/BSS。
拟以JMP进入，不产生额外CALL帧；暂用16字节栈保存D0、D1、A0和PSW。按word清零
恰好16 KiB，然后恢复寄存器与PSW、回放原厂MOV、JMP回60020204。没有C、RTOS、
allocator、MDR、循环寄存器或已初始化全局状态依赖。

|最终链接必须绑定的符号|拟定含义|
|---|---|
|`__ep7_private_uncached_start`|已取得独占资格且4字节对齐的16 KiB payload；当前提案a1dd4d00|
|`ep7_stock_boot_next_copy_end_unresolved`|原MOV读取的word地址6218d984|
|`ep7_stock_boot_after_clear_unresolved`|原指令结束后的60020204|

候选 `a1dd4d00..a1dd8d00` 的64字节后置守卫不属于清零区。桥本身没有“运行一次”
标志，必须靠真实冷启动接续保证仅在私有状态使用前执行；不得用于热重启或活跃对象重置。
最终代码区、跳转填充方式和链接地址尚未决定，没有生成原厂接续补丁。

## 必须随启动前缀生效的池上界

同时纠正[RAM方案](RAM_OWNERSHIP_AND_BUDGET.md)的一项加载归属：分配/释放上界
`600229b9/60022c28` 位于 `60022xxx` 启动前缀，**不在60030000起的kernel复制中**。
若保留CPU2大块池末槽，两个上界修改必须随启动前缀的原厂加载生效，先于任何相关
分配；不能依赖600201f9才加载这些修改，更不能在池已使用后缩容。启动前缀的实际
加载者与守卫初始化者尚待追踪。本批没有批准保留区或修改这两条指令。

## 定向检查及边界

- [启动顺序脚本](../../tools/ep7_cold_start_order.py)与[报告](../../research/ep7/cold-start-order.json)：
  当前解码main的79条精确指令和完整6字节接续通过。

  实际生产汇编的字节/四处重定位匹配；仅在合成地址链接，明确禁用relax。
- 两种PSW初值下，32个寄存器与“执行原MOV后到达接续”的期望一致；4096次payload
  word写入、4次栈保存，payload和16字节栈暂存以外逐字节保持原状。
- 三个负控制检出：省略PSW恢复、多写第4097个word损坏守卫、跳过原MOV回放。
