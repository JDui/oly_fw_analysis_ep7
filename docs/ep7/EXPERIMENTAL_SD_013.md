## 操作

进入 COLOR 色轮，删除键循环 **Sat → Lum → Hue → Sat**。
前拨轮选色区，后拨轮调数值，INFO 切单色区／ALL；四组 COLOR 的 H/L 分别保存。
范围保持 E-P7 的 −5～+5，正常退出、保存和复位沿用原有操作。

## 修改

在现有两个捕获转换器之外，补上 `60324071` 的紧凑参数正向转换。
它把 3096B 参数对象中的模式、COLOR 组和 Sat 数组传入已构造的处理任务。
013 在该路径 Sat 拷贝完成后，按源对象的 COLOR 组取得 H/L 并写入该任务的 24B 尾部；
后续 COLOR builder 与原厂上传循环使用这份参数。
反向查询分支不重新采样 H/L；非 COLOR 正向更新将 H/L 中和。
这是原生参数传递中的缺口修复，连续实时取景的调度与屏幕效果仍需机身确认。
正向更新成功后，原厂会重新清理操作记录并将 stage index 置零；
已检查的更新提交与阶段调度不以 Sat 是否同值决定跳过，所以没有新增伪改 Sat 的强制刷新。

标题改为 96×40 的短条背景，使用原厂 layer1 背景色索引 1；
对应已核对的原厂 CLUT 5／53 条目是 `0x88000000` 半透明黑，文字继续由 layer2 绘制。
页面观察器更新后标记整个 GUI 根区域重绘，包含旧标题所在区域；
曲线等非色轮类别不绘制背景或轴文字。

## 定向检查

以压缩包内绑定最终构建的 `evidence/` 为准：

- 实际 H1 读取、捕获／克隆与两个转换器的原有传递路径。
- 紧凑对象正向 Sat 拷贝 → H/L 快照 → COLOR builder → 两个模拟 MMIO 上传窗口。
- 反向查询不改冻结参数，非 COLOR 更新不读 H1 并中和旧值。
- 原生背景绘图、文字布局、隐藏类别两层不绘、两个页面更新入口的整页清理。
- 原有 H1 原厂 bank 读写／保存召回、加载驻留、封装、原生 mode1 路由及 ZIP 回读。

模拟的设置、页面对象、字体资源和最终像素后端均有明确边界。
参数上传窗口使用 RAM 模型，不是实际 ISP 像素；文字提交也不等于机身显示验收。
不做 SHA 校验，不重复完整原生 mode2 解码。
