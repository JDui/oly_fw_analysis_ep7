# EP7HSL 005 实机黑屏事件

2026-11-01。**005 的实机正常启动未通过；暂停安装及重复刷写该实验包。**
保留原始固件、ZIP 和离线报告作为故障输入，不在原文件名下静默替换新程序。

## 现场观察

- 用户报告刷写指示明确先常亮，再快速闪烁；随后拨电源关机重开。
- 用户确认重开前已取出更新卡，没有按住 OK；AF 灯熄灭、屏幕持续黑屏，菜单与回放
  均无反应。因此不能只用“仍停留在更新模式”解释这次观察。
- 用户随后重新使用 `install` 中的实验包刷写，仍观察到先常亮再快闪。已说明持续等
  完成快闪不能证明新程序能启动，并建议完成当前轮后回刷 `restore-stock` 原厂包。
- 用户随后明确反馈：“原厂回刷后已恢复画面和菜单”。本次故障状态下的 SD 原厂恢复
  已有现场成功报告；尚未读取相机 flash、PC/错误码、串口或硬件调试状态。

这些是用户现场报告；尚不能证明五个组件的物理写入和回读全部成功，也不能认定永久
损坏。本次恢复成功只适用于此次状态，不证明任意启动损坏都可恢复，也不等于独立
启动 ROM/USB 救援能力已经成立。照片处理与 H/L 验收尚未开始。

## 当前恢复路线

现有原厂文件为
`generated/ep7/flash-packages/EP7HSL-005-EXPERIMENTAL/restore-stock/DCOLYMP/E1429999.BIN`。
它在交付检查中与原厂五组件输入逐字节一致，长度 111,017,984B；没有 H/L 修改。
不要误用同名的 `install/DCOLYMP/E1429999.BIN`。

按当前已采用的 SD 路线，只在确认常亮转快闪的完成指示后拨 OFF；关机后取卡，替换
卡上的更新文件为原厂文件。关机插卡、按 OK 开机、指示开始后松开；常亮时保持供电，
完成后拨 OFF、取出更新卡、不按 OK 正常开机。未知指示没有已验证的强制断电时长。

完成快闪及关机步骤来自 fishcu 的
[PEN-F 安装说明](https://github.com/fishcu/oly_fw_analysis/blob/alpha-20261017/releases/alpha-20261017/INSTALLATION.md)，
本次用户观察到了相同指示顺序；这不是 E-P7 官方恢复文档。原厂回刷仍依赖更新路径
能够运行，不是本机完整备份或独立救砖方式。

## 软件排查：事实与假设

1. `runtime/cold_bootstrap.c` 会在原厂 `60191371` 调用位置检查当前任务、冷启动
   上下文、安装组、私有锁及五个队列；失败进入 `0xf01..0xf06` 终止分支。
   `runtime/quarantine.s` 清除本核普通中断使能位，并永久循环。该行为能够阻止
   后续原厂任务启动、造成黑屏，但尚未从机身取得证据证明命中了哪一分支。
2. 原厂 `60030afa` 的任务初始化把 TCB+48 设为 1；原厂段初始化 `6004586c`
   使用 `1 << (段号 - 1)` 并在结束时合并到 `a272e41c`。这支持两项检查的静态
   来源，但不证明现场值在新增 bootstrap 时仍然符合全部假设。
3. 交付前的启动模拟显式提供当前任务、就绪/等待链表及队列对象/缓冲区；未执行
   完整内核静态对象创建、物理缓存/多核时序或整机启动。下节针对原生静态分配补充
   检查，仍未得到运行到该 bootstrap 的真实机身状态。
4. 原厂启动前缀保持相同、容器被原生更新器接受、加载复制及局部 GUI/worker 模拟
   通过，都没有验证新程序在实机的完整启动。这次故障不被历史通过项覆盖。
