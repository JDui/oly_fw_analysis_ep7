## 用户更正及当前范围

用户明确更正：不是完全富士式靠提高 ISO 换动态范围，而是“优化高光压制的映射与曲线来提升 JPEG 的高光动态范围”。原先把降低模拟增益及配套亮度补偿作为主线，是对目标的误读，现已停止推进。

当前方案不改变 ISO、Auto ISO 上下限、Tv/Av、曝光补偿、AEL、模拟／数字采集增益，不引入多帧或额外曝光。主目标是在原始数据尚有层次的范围内，避免 JPEG 映射过早把不同高光压成同一纯白，并保持自然的中间调和高光过渡。不能恢复传感器、白平衡或其他前级已剪掉的信息。

旧[增益设计](SINGLE_FRAME_DR_GAIN_DESIGN_ARCHIVE.md)及[实现记录](SINGLE_FRAME_DR_GAIN_IMPLEMENTATION_ARCHIVE.md)仅作研究归档；其中 ISO400/800 门槛、Auto ISO floor、曝光票据及降增益补偿不再是当前功能要求。旧 `EP7DR` 候选不得用于本方案。

后续设计、实现及验收均由原对话负责，不再派发其他执行代理。遵循不做 SHA、复用既有实现、只测试关键不确定因素的约束。

## 设置与交互

022 补齐 HDR 改档后的处理通知：成功写入／入队后复用 015 `ep7h_refresh`，由
对应 COLOR 回调调用原厂 `602b8916`；在设置临界区之外执行。单纯重绘曲线 UI
不能替代取景参数刷新。INFO、无效操作和拨轮边界不通知；长 OK 改回 OFF 会通知。

沿用原生曲线入口：

```text
高光／阴影 --INFO--> Midtone --INFO--> HDR 等级 --INFO--> 高光／阴影
```

- `OFF / 200 / 400` 暂保留用户原命名。200 为较温和的高光映射，400 更强；不表示动态范围翻倍、1/2 EV 或必须升至某个 ISO。
- 两拨轮逐档切换，边界停止；INFO 只处理按下，释放不切页。短 OK 沿用原厂退出；长 OK 仅复位当前 HDR 等级。
- 保留原有高光、阴影、Midtone、COLOR H/L/S 值；不占用色轮 INFO/ALL 或 Delete S/L/H。
- 每次重建曲线页从高光／阴影进入，所选 HDR 等级仍保留。HDR 页显示三档和选中项；不再显示 ISO400+/ISO800+ 条件。
- 普通曲线组、COLOR1–4、MONO1–4 共九个已核对作用域，继续使用原厂 ACTIVE part-1 标签和 bank 生命周期。读取旧值／无效标签为 OFF。
- 当前实际映射只支持 COLOR1–4；其余模式可保存选择但显示 N/A。内部处理请求仍需通过兼容性检查。COLOR 没有供用户手动选择“灰阶标准”的入口，不将内部 Gradation 条件写成用户操作；未知内部请求由固件侧诊断。
- 与原生曲线一样，这属于渲染设置。RAW-only 不被强制改成 JPEG，也不改 RAW 采集值；可保留选择用于预览和以后 JPEG 拍摄。是否影响嵌入预览取决于其原生处理路径，不能当作已验证功能。
- 原曲线页的紧凑状态标记仍待找到不遮挡原生读数的位置。不得为叠标覆盖本地化帮助文案。

## 映射位置与当前曲线

继续复用已定位的 RGB gamma 选择和缓存入口 `603ae830`：原厂选择成功后、原厂缓存比较及系数计算前，替换同一请求的三张相同 RGB LUT 指针。维持原生上传、亮度曲线和 H/S/M/HSL 路径。

普通与复用颜色表路径统一在原厂 selector 返回后按其实际结果检查。不能仅因
request+1524 非空就跳过普通 COLOR；仍只接受三通道相同且属于已核对 ROM 表的
指针，不改写共享的复用对象。020 临时显示 V/P 处理观测以验证实际接线，记录不
参与渲染决策，也不等同于 ISP 像素完成。

021 补齐原厂 `603aaced` 支持的类型 0/16、来源 family 1/2。两种类型均由该
分发器送入相同的 COLOR 配置；类型 3 的格式转换阶段仍保持原厂处理，避免重复
映射。类型 Ex、来源 Fx 中 x 是字段值的十六进制显示，15 及以上饱和为 F。

022 依据被冻结的 COLOR 来源资格，替代后续请求键必须为 11 的重复限制。等级
只由 COLOR1–4 源采样器写入，其他来源或新任务为 OFF；所有 owner、pass、特殊
标志及原表检查保留。023 的成功码高位仍以 4/7 区分请求键，低位 1/2、3/4、5/6
分别表示三组底表中的 200/400。
selector 返回 0 也进入只读诊断分支显示 C0，保持其原生输出，避免这一分支留下
之前的成功记录。未调用 observer 的其他处理分支仍不能由最近码推断。

原厂 Normal Gradation 三组 256 节点、12-bit 输出 LUT 分别在节点 237、243、237
首次到达 4095。HDR 直接替换这一级输入到输出的映射，之后仍有原厂 10-bit 亮度
LUT，处理对比度和 H/S/M。[同版原厂亮度 LUT 研究](https://github.com/cakelesscoder/caduceus-ep7/blob/main/docs/TONE_ENDS.md#12-curve-format)

022 以固定输入节点 48 起压，三组表在此节点的输出亮度差异很大。原厂输出为
3968 时，022 的 HDR400 分别压 553、263、227 码。正二次尾部还会使亮端斜率
重新增大，例如第一组 400 的斜率先降到每节点 5 码，再升到 12 码。

023 保留至原厂输出首次达到 2560 的节点。设之后的归一化节点位置为 t，原厂
起点为 y0、距白点为 D、起点斜率乘以节点跨度为 S，肩部采用
`y0 + D*t + (S-D)*t*(1-t)/(1+b*t)`。两档各自用原厂输出 3968 的节点定标，
分别压 168、336 个码。构建时用精确有理数计算，最后取整。相机只读取生成的表。
六张表要求肩部严格递增，量化前斜率逐渐减小，端点为 0/4095，各节点保持
`HDR400 <= HDR200 <= OFF`。由传感器或前级处理已经剪掉的层次超出该曲线的作用范围。

## 逐帧参数和回退

直接扩展 015 已有的采集 owner、唯一临时 clone、五个实时预览 owner 及成功的参数 setter。每个 owner 冻结一次等级；拍摄后切档、池位复用不得改写已冻结的照片。取景使用自己的原生 owner，不借用 capture 指针。

同一原生 job 在已有 24B HSL 尾部后增加 4B 等级，构造器统一扩容并清零。新 observer 原样尾调用 015 helper，保留其寄存器、HSL 数据和生命周期。原厂 RGB 缓存依据不同不可变 LUT 指针自然刷新。

不再需要“采集降增益必须补偿”的义务或失败钩子。未知 owner、bank 事务不稳定、未知 LUT、非兼容 Gradation 等直接保持原厂渲染，不强制中止拍照。关闭后恢复原厂指针。参数快照与缓存一致性仍须验证，但不再研究本功能的 sensor gain/frame 回执。

## 最小验收

1. 构建清单只含曲线 UI、设置 bank、015 参数 observer、RGB pre-cache 和尾部扩容；原来曝光／增益／捕获属性／强制失败钩子全部不在新候选中。
2. 六张 LUT：前段、端点、单调、两档强弱、无增亮、纯白终点；不将数学曲线当作真实像素增益证明。
3. 同镜像回放：A/200 clone 在 B/400 和池位复用后不变；预览独立冻结、复用和关闭；原厂 HSL 不变；不同 LUT 触发原生缓存更新。
4. 同镜像 INFO 三页、两拨轮、局部复位、重建和清理；ISO200 与 Auto ISO 不因旧门槛显示不可用。
5. 原生 bank 写读、跨核事务和早期加载守卫的定向检查。物理关机保存另记实机状态。
6. 后续像素验收用同一曝光、ISO、白平衡、光圈、快门的 OFF/200/400，比较高光纹理、中灰、彩色高光、渐变；不能用减曝光照片替代对照。
