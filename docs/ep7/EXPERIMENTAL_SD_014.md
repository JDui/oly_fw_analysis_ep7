# EP7HSL 014：取景帧来源修正与实心标题

2026-11-02，E-P7 原厂 1.1 / build1100。

013 的实机结果：小块半透明背景正常，但标题只有描边；H/L 在退出色轮、切换 COLOR 组后
仍不影响取景，保存的 JPEG 保持正确。014 按这些结果修正参数来源与文字填充。

## 使用

删除键仍循环 **Sat → Lum → Hue → Sat**，拨轮与 INFO／ALL 使用原厂操作。
H/L 以四个 COLOR 组分别保存，范围 −5～+5。标题使用半透明黑底、实心白字与黑色描边。

## 这次修正的原因

013 对紧凑参数的字段解释错误：+2116 是 Live HDR 类型，+2117 是 ColorCreatorHue，
并不是 COLOR 模式与组号。旧模拟手造了 HDR=11 的输入，重复了实现的错误假设。
014 移除该判断与挂点，改为在原生五个 980B 取景参数槽中读取真实字段：
原生 raw mode 位于 +941、COLOR selector 位于 +944、十二个 Sat 半字位于 +704。
字段已沿 typed getter、68B 发布队列与原生槽复制过程逐项核对。

H/L 在原厂 Sat 取得后冻结到对应槽的 24B 行；每帧原生 setter 成功后，
从同一已取得槽复制到该任务的 H/L 尾部。原厂跳过刷新或 setter 失败时遵循其原语义，
不在后续 ISP 回调中猜测当前 GUI 预设。

此外补齐使用原生 borrowed table 的 COLOR packer 分支，并明确检查请求 raw mode=11，
保留非 COLOR 的原始输出与原有 table 数据。原有 JPEG 捕获、克隆和处理路径继续验证。

013 借用的首个文字样式是 0／15／15，文字层 CLUT 6／54 的 0 为透明色。
014 保留字体与几何，将颜色明确设为 4／16／16：不透明白色正文、黑色描边与阴影。
半透明背景和切页时整页清理继续使用原生绘制与损伤区域流程。

## 验证范围

最终执行范围及模型边界以包内 `evidence/` 为准，包括真实模式块复制、H1 读取、
取景槽采样与任务传递、普通／借表 COLOR 系数、文字填充／描边与原生绘图提交。
设置、内存对象、字体与最终像素后端仍有模型边界；原生参数上传不等同于 ISP 像素验收。
实际实时取景、标题显示、切页清理和 JPEG 仍须由 014 机身确认。

封装复用五组件流程与原厂加和校验，执行 mode1 路由、错误停止、文件回读和 ZIP CRC；
不做 SHA 校验，不重复完整 mode2 解码。本轮未写相机或 SD 卡。
