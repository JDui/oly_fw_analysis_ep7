拥有实现、必要定向验证、实现报告。可以直接协调修复，不重复向用户询问实施许可。

## 2. 产品目标和命名

单次曝光，输出普通 SDR JPEG，在主体亮度基本一致时保留更多高光层次，并控制暗部噪声。
UI 沿用用户称呼 `HDR Level`，选项 `OFF / 200 / 400`；说明中明确“单帧高光保护”，
内部代码使用 `single_dr` 或同义独立命名，区别于原厂多帧 HDR1/HDR2 和 LiveHDRType。

| 等级 | 编码建议 | 高光保护设计目标 |
| --- | --- | --- |
| OFF | 0 | 完全沿用 015 的曝光、处理和现有 HSL |
| 200 | 1 | 相对普通同标称 ISO 渲染，预留约 1 EV 高光空间 |
| 400 | 2 | 相对普通同标称 ISO 渲染，预留约 2 EV 高光空间 |

数字表示工作策略，不能当作已测得的传感器总动态范围增量。首版不增加 AUTO、多帧合成、
新色彩模式、CPU 全图处理或独立 JPEG 编码器。200 和 400 都是最终交付要求，
可以先实现 200 验证链路，但不得把仅有 UI 或 200 的结果报作全部完成。

## 3. INFO 交互合同

入口复用目前原生 Highlight & Shadow 曲线入口，不增加顶层菜单或 HSL 类别。

```text
高光／阴影 --INFO--> Midtone --INFO--> HDR Level --INFO--> 高光／阴影
```

| 操作 | 高光／阴影、Midtone | HDR Level |
| --- | --- | --- |
| INFO 短按 | 依上图切页；保留原生曲线数值 | 回到高光／阴影，不改变等级 |
| 前／后拨轮 | 原厂对应的曲线调整 | 任一拨轮逐级 OFF→200→400，逆向相反，边界停止 |
| OK 短按 | 原厂退出／确认语义 | 接受当前设置并退出；保存走原厂设置生命周期 |
| OK 长按 | 保留原厂复位范围 | 仅把当前作用域 HDR 等级复位 OFF，不碰曲线或 HSL |
| 半按快门、MENU、回放 | 原厂行为 | 正常离开编辑态，遵循同一设置语义 |
| 删除键 | 原厂行为 | 不切 HSL 轴；不额外承接删除动作 |

INFO 必须在真实原生曲线 owner 和实际输入状态下匹配，不能全局截获。
色轮内 INFO 的单色区／ALL 和删除键 S→L→H 保持 015 行为。一个实体短按只切一次，
不把 press/release 都算一次；按住 INFO 不高速轮转页面。切页本身不写设置。
每次重新进入曲线编辑器从原厂高光／阴影页开始，保存的 HDR 等级继续保留。

绘制复用现有原厂字体、原生重绘与页面清理。三档横向可见，当前档突出；原生 UI 只能
容纳较窄文案时用 `HDR OFF / HDR 200 / HDR 400` 加底部 INFO 提示。
HDR 页不把高光／阴影图像伪装成 HDR 曲线，不显示无依据的“提升几档”实测数值。
开启且可用时在原曲线页保留紧凑 HDR200/HDR400 状态，不能挡住曲线或原生读数。
切回、退出、模式变化时无残留；不增加旧 005–010 式共享 MVC 类别／大运行时框架。

## 4. 设置作用域与不可用状态

HDR 等级随当前原生曲线预设保存：COLOR1–4 各自独立；普通图像模式及 MONO 使用其
原生曲线设置实际共享／独立的作用域。实施前必须给出作用域映射，不能自行假定每种
图像模式都有独立存储。首次读取旧设置、无标记或无效编码时为 OFF。

复用已证实的原生 settings/bank 机制和合法扩展字段。不能覆写 H1 两轴数据，不能
把保留字节猜作空闲，不能新增每次拨轮直接写 flash 的路径。正常关机、原生保存召回、
复位及旧 015 数据迁移须保持一致。若可用存储字段尚未确立，记录缺口并继续研究，
不把易失原型包装成完整可保存功能。

区分 `selected_level`、`effective_level`、`inactive_reason`。低 ISO、特殊模式或
已知不兼容设置下保留用户选择，并明确显示如 `HDR 400 (ISO >=800)` 或 `Unavailable`；
实际走 OFF。条件恢复后只在后续新捕获上恢复所选等级，已经开始的照片不改变参数。
HDR 页无条件提供 OFF；暂不可用的 200/400 可以预选，但必须同时提示当前未生效。

## 5. 成像策略：优先真实增益解耦，禁止仅改亮度

首选验证富士式路径：标称 ISO 供测光／AE 和输出亮度决策，采集模拟增益较其降低
一档（200）或两档（400），然后在未丢失高光的处理域恢复中间调，
用平滑 shoulder 压缩高光。为避免歧义，数学定义为 d∈{0,1,2}、倍率 r=2^d，
`capture_gain ≈ nominal_gain/r`，中间调补偿倍率约 r，实际映射须依原生标定。

必须区分标称 ISO、模拟增益、数字增益、光圈／快门决定的光子曝光。降低后端数字增益
不能恢复前端已饱和数据；降低模拟增益也不能恢复已达到传感器满阱的信号。
不能只改 EXIF、只扣曝光补偿或对截断后的 JPEG 压高光就宣称 HDR200/400 实现。

若 E-P7 正常最低模拟增益对应 ISO200，则按该路线预期 200 需要标称 ISO≥400，
400 需要≥800；这是待核对的设计条件，不能仅从菜单 ISO200 推导硬件增益基准。
应由已确认的增益表生成最低值，不把 400/800 写成未经证实的硬件事实。

| 曝光模式 | HDR 的期望行为 |
| --- | --- |
| P/A/S，固定 ISO | 保留该标称 ISO 的原生 AE／用户补偿；达到增益条件后降低实际采集增益并配套映射 |
| P/A/S，Auto ISO | 在原生 Auto ISO 合法域内提高最低标称 ISO 至所需下限，不突破用户最高 ISO；无交集则暂不可用 |
| M，固定 ISO | 保留用户设定的快门、光圈、标称 ISO；只在已证明的增益解耦条件成立时生效 |
| M，Auto ISO | 仅在原生支持且 Auto ISO 约束可闭合时按对应 Auto ISO 规则执行，否则提示不可用 |

固定 ISO 低于门槛时不擅自改为 ISO400/800，不静默改变用户快门或光圈。
曝光补偿、AEL、拍摄前锁定应继续使用原厂语义；HDR 差额不得累积叠加或写回用户 EV。
曝光／增益和映射必须使用同一捕获快照，逐张冻结，不能在 ISP 回调读取当前 UI 档位。

如果原生架构无法解耦模拟增益，实施线程必须说明实际限制，并提出“AE 减少真实曝光＋
配套曲线”的备选合同供原对话审查。该备选会改变快门／光圈、M 模式和低 ISO 体验，
不可未经更新本设计就静默替换。允许继续独立 UI／定位工作，但不发布伪功能。

## 6. 曲线、图像模式、取景、RAW

优先复用原生 Gradation Auto、gamma／亮度 LUT 及 ISP 参数上传。先证明输入域、
位深／端点和截断位置；CPU 配置调用顺序不等于 ISP 像素执行顺序。
使用原生曲线族或离线预计算 LUT，保持单调、端点可控、中间调自然，避免明显色偏、
断阶及提前通道剪裁。无需第一版自写局部色调映射。

用户高光／阴影／Midtone 数值不被重置或覆盖。HDR 补偿作为底层曝光归一与压缩，
用户曲线作为保留的风格调整；实际可组合顺序由原生 ISP 路径决定并记录。
明确检查 Gradation Auto 是否已有曝光／曲线补偿，避免重复补偿。不能证明能组合的
模式以清楚的不可用原因处理，不能悄悄改写用户的 Gradation／图像模式。

自然模式和 COLOR1–4 是核心交付；其他有原生曲线的普通静态图像模式应沿用同一
受支持路径。MONO 等若有不同链路需单独限定，不猜测兼容。原厂多帧 HDR、ART、
SCN/AP 特殊合成、视频、B／LiveTime／LiveComposite、闪光等首版不叠加。
普通单张为首要资格；连拍仅在逐帧快照和状态切换已证实时启用，否则明确停用该扩展。
电子／机械快门本身不是 HDR 等级开关，不把不同快门的 ISO/增益限制假定为相同。

取景应反映中间调补偿和高光压缩，与 JPEG 的方向一致；实时取景可能具有独立增益及
自动提亮，必须追踪两个路径而非直接复制 capture 指针。UI 数字正确不等于预览生效。
H/L 015 的普通／borrowed COLOR 分支、逐帧 owner、捕获／clone 路径继续有效。

RAW 保留真实采集数据；实际降低采集增益必然可能改变 RAW 数据及其开发所需参数。
记录标称／实际增益及现有 RAW metadata 的处理，优先原生可表达字段，不改坏 ORF。
不承诺第三方 RAW 软件与直出效果一致，不伪造 RAW 不受影响。首版 JPEG 或 RAW+JPEG
拍摄生效；RAW-only 暂停此 JPEG 功能并显示原因，避免只有隐性采集变化。

## 7. 原生研究与实现顺序

1. 读取本设计、015/014 说明及当前原生 HSL 实现，列清可复用入口。研究资料中的
   `compact+2116=LiveHDRType` 是原厂其他字段，禁止当新等级存储或直接启用开关。
2. 建立 E-P7 1100 原生三条链：曲线 INFO 的实际 owner/事件/重绘；曝光／模拟与数字
   增益的生产消费；gamma／tone／Gradation 的输入域与请求上传。采用可核对的源窗口，
   不把名称、相似地址或自制 fixture 值当语义证明。
3. 先闭合 OFF 与 200 的采集—映射对照，再实现 400；定向报告明确每个模型边界。
4. 以最小钩子添加曲线第三子页、合法设置存储及捕获／取景传播；保留原厂公共任务、
   队列、清理路径，不重建 005–010 的大运行时框架。
5. 最终候选通过下面关键验收后，复用现有构建与封装流程生成本地实验包（若原生链路

## 8. 验收：少量关键证据，不跑无关大套件

### 原对话的软件验收门槛

- 检查实际 diff 和绑定最终候选的证据，确认不是只有 UI／host stub；OFF 不改变
  015 的曝光／ISP系数／HSL。可直接字节比较关键窗口，不执行 SHA。
- 一组真实原生曲线事件路径验证 INFO 三页、两拨轮、局部复位、退出清理，并证明
  色轮 INFO/ALL 与删除键没有被误接管；不再用手造错误模式验证同一错误假设。
- 一组必要曝光边界：OFF/200/400、固定 ISO 下限两侧、Auto ISO 上限冲突、M 固定、
  一个明确不兼容模式；证明采集和曲线同步生效／同步回退，OFF恢复无残余增益。
- 最小保存／快照检查：至少两个 COLOR 组区分，旧数据默认 OFF，原生 bank 召回，
  捕获后切级不影响在途照片，取景及 JPEG 使用同一有效等级语义。
- LUT 如有变动，仅验证单调性、端点、中间调、高光过渡及定点范围；这是算法检查，
  不能等价为物理动态范围效果测试。
- 若生成 SD 包：沿用原厂加和、五组件封装、实际候选回读和既有必要路由检查，避免
  重跑未变的完整 mode2 或扩大到无关回归。不能把旧构建报告挂到新二进制上。

### 实机画质／交互验收，待用户有条件时由原对话统一对接

一处固定白平衡、固定光圈、静态高反差窗景，以相同标称 ISO800、相同光圈／快门
拍 OFF/200/400 三组 RAW+JPEG，观察：原始值／metadata 是否符合采集增益策略；
中间调亮度是否基本一致（初步目标差异≤约0.2EV）；高光是否新增真实可辨纹理；
暗部噪声、肤色／彩色高光及渐变是否可接受。不能只比较“白色变灰”的面积。
该场景检验相对同标称 ISO 的高光保护，不宣称优于 ISO200 的最优单次曝光。
另用一个低于门槛 ISO 确认不可用提示／OFF行为，正常关机一次验证设置保存。
没有相机像素数据时保持“软件验证完成、实机待验收”，不宣布动态范围提升已实现。
