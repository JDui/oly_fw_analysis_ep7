# IRQ入口、独立栈与返回任务栈的责任

2026-10-31。本节点把常规IRQ软件路径定位到两个明确的SP切换点，避免把整条中断
处理链都算到Usr3，或反过来认为独立中断栈意味着Usr3完全不付出栈空间。
**未裁剪分支的单次已知部分为被中断SP以下104字节；完整上界仍为null。**
后续定向检查已识别扩展寄存器指令和IRQ退出屏蔽条件。TCB+48在查询时仍为1的
条件路径，其已知部分为96字节；该条件的整个bootstrap有效期仍未证明。

## 向量和独立栈

启动前缀6002008c..600200c8把七个入口的低半字写到8000..8018：60030020、
60030058/60/68/70/78/80。各入口汇合到600386f8；level0入口先用当前SP以下8字节
暂存D0/A0并记录诊断状态。这里只证明原厂软件写入意图；硬件向量基址、启动前缀
的上游装载与实际寄存器行为仍未验证。

domain0 root600411a4的+112和+116分别为6218f200和8192。常规IRQ最外层路径使用：

|对象|地址/大小|
|---|---|
|独立IRQ栈区间|6218f200..62191200，8 KiB|
|初始IRQ工作SP|621911f8，即栈顶−8|
|保存原任务SP的word|621911fc，即工作SP+4|
|保存、切入|60038743保存SP；60038746装入IRQ SP|
|读取、切回|600387f9读取word；600387fb恢复任务SP|

root+28所指字节为0才切入独立栈；非0的嵌套IRQ继续使用已经活动的IRQ栈。
60038759递增该字节，退出时递减；最外层最终清0并恢复任务SP。独立栈的所有handler
及其8 KiB容量未在本节点证明，不能据地址和配置值直接宣称中断栈安全。

## 切换前后各占多少

进入600386f8后，显式SP变化依次为MOVM保存40、ADD释放4、60030107扩展保存16、
60038708再分配4，总计**56字节**。可选入口hook来自root+276，原厂指向60073218，
当前只有`retf [],0`。它在切栈之前，故必须保留原厂绑定或另行计入其栈成本。

切回任务SP以后，仍会调用60031a76、6003593f、60036884和任务异常服务。复用上一
节点的CFG/SP分析，14个可达函数的正常返回帧均匹配；这段已知部分最多40字节。
尾部显式恢复顺序为+4、+16、−4、MOVM弹出40，恰好撤销保存的56字节，然后RTI。

[GNU MN10300中断入口](https://gnu.googlesource.com/binutils-gdb/+/cbe950e9fe8a56f788bcf985cc51733f18abb45b/sim/mn10300/dv-mn103cpu.c)
模型把PC和PSW保存到8字节区域；已有GNU RTI函数体恢复PSW/PC并将SP加8。原厂入口
及6003883a的RTI布局与此一致。因此本轮记录的**单次已知部分**为8+56+40=104。
GNU模型的中断控制器地址并非E-P7寄存器资格证据，不把模型当成相机执行。

## 扩展指令与退出屏蔽条件

[松下MN103001G/F01K原厂手册的镜像](https://www.manualshelf.com/manual/panasonic/personal-computer-mn103001g-f01k/user-manual-english.html)
第61–65页把五条寄存器形式对应为：

|原厂位置|GNU名称|手册名称|本序列中的传送|
|---|---|---|---|
|6003010a|UDF13 D0,D0|GETCLX|MCRL→D0，MCVF→V|
|60030112|UDF12 D0,D0|GETCHX|MCRH→D0，MCVF→V|
|60030116|UDF15 D0,D0|GETX|MDRQ→D0|
|6003012c|UDF21 D0,D1|PUTCX|D0→MCRH、D1→MCRL、V→MCVF|
|60030130|UDF20 D0,D0|PUTX|D0→MDRQ|

完整save/restore helper的23条指令现逐条匹配，包括SP下16字节内的四个word与
仅提取bit3的恢复逻辑。手册定义的这些寄存器传送不额外改SP、访存或调用；因此在
该架构模型下不增加已计的16字节。这里没有自行实现UDF模拟器，也没有执行相机芯片，
不能把MN103001G型号等同于E-P7 SoC；流水线flag时序与完整寄存器回转仍未实测。

root+348为0800。按照[手册的优先级规则](https://www.manualslib.com/manual/119167/Panasonic-Mn103001g-F01k.html?page=50)
和上述GNU入口代码，普通IRQ需要IE为1且请求级别小于PSW屏蔽级别；0800的级别为0，
没有符合条件的普通IRQ。不能只看到IE=1便认为已经开放普通中断。

60038775先应用该mask。600387b1..600387b8确实暂时恢复原PSW处理deferred service，
但此时仍在IRQ栈上；正常返回后600387c1重新应用mask，随后才在600387fb切回任务SP。
若6003434b观察到当前TCB+48为1，它返回0，60038819跳过6003881e的原PSW恢复和
60038822的任务异常调用。随后60030126只把保存的V位并入当前PSW，不改变IE/LM；
MOVM恢复不包含PSW，最终RTI才恢复被中断状态。

复用现有CFG，四个决策前callee及其直接后继共10函数、257条不同地址指令，无显式
PSW写入或UDF。调用帧及其可见后继的最大已知成本为32字节，故条件路径的已知部分为
8+56+32=96。原scheduler的间接回调、SP切换、restart和BREAK边界仍保留；仅对保持
已审绑定、没有跨越这些未决边界的连续返回路径，排除了此段普通IRQ再次嵌套。

## 仍不能合成完整任务上界的原因

- **架构模型边界**：五个UDF已有手册对应和完整原厂helper匹配；相机SoC与参考模型的
  一致性、flag流水线和实际IRQ时序没有执行验证。
- **任务异常回调**：60038822仍可在任务栈上进入6003436e及TCB+52 handler。
  [bootstrap现场检查](COLD_CONTEXT.md)已实现TCB+48为1的观察，其后有效期尚未闭合。
- **嵌套窗口**：6003881e在异常callback之前恢复原PSW。不能在该窗口未审完时，
  把条件路径96替换通用结果104，或与416相加后宣称完整任务峰值。
- **故障路径**：BREAK/NMI/debug不是本报告的常规IRQ路径；原厂60030008会转入诊断
  代码60055250，其中继续调用其他服务。自有quarantine已在后续[现场节点](COLD_CONTEXT.md)
  改为无显式trap循环，原厂故障处理保持不变。

后续节点已落实TCB+48现场检查和自有终止体；剩余为资格有效期、context切换与故障/嵌套。
没有通过写TCB关闭任务异常，没有修改原厂IRQ handler或扩大栈配置。
