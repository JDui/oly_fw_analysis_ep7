# IRQ入口、独立栈与返回任务栈的责任

2026-10-31。本节点把常规IRQ软件路径定位到两个明确的SP切换点，避免把整条中断
处理链都算到Usr3，或反过来认为独立中断栈意味着Usr3完全不付出栈空间。
**单次路径的已知部分为被中断SP以下104字节；完整上界仍为null。**

## 向量和独立栈

启动前缀6002008c..600200c8把七个入口的低半字写到8000..8018：60030020、
60030058/60/68/70/78/80。各入口汇合到600386f8；level0入口先用当前SP以下8字节
暂存D0/A0并记录诊断状态。这里只证明原厂软件写入意图；硬件向量基址、启动前缀
的上游装载与实际寄存器行为仍未验证。

domain0 root600411a4的+112和+116分别为6218f200和8192。常规IRQ最外层路径使用：

|对象|地址/大小|
|---|---|
|独立IRQ栈区间|6218f200..62191200，8 KiB|
|初始IRQ工作SP|621911f8，即栈顶−8|
|保存原任务SP的word|621911fc，即工作SP+4|
|保存、切入|60038743保存SP；60038746装入IRQ SP|
|读取、切回|600387f9读取word；600387fb恢复任务SP|

root+28所指字节为0才切入独立栈；非0的嵌套IRQ继续使用已经活动的IRQ栈。
60038759递增该字节，退出时递减；最外层最终清0并恢复任务SP。独立栈的所有handler
及其8 KiB容量未在本节点证明，不能据地址和配置值直接宣称中断栈安全。

## 切换前后各占多少

进入600386f8后，显式SP变化依次为MOVM保存40、ADD释放4、60030107扩展保存16、
60038708再分配4，总计**56字节**。可选入口hook来自root+276，原厂指向60073218，
当前只有`retf [],0`。它在切栈之前，故必须保留原厂绑定或另行计入其栈成本。

切回任务SP以后，仍会调用60031a76、6003593f、60036884和任务异常服务。复用上一
节点的CFG/SP分析，14个可达函数的正常返回帧均匹配；这段已知部分最多40字节。
尾部显式恢复顺序为+4、+16、−4、MOVM弹出40，恰好撤销保存的56字节，然后RTI。

[GNU MN10300中断入口](https://gnu.googlesource.com/binutils-gdb/+/cbe950e9fe8a56f788bcf985cc51733f18abb45b/sim/mn10300/dv-mn103cpu.c)
模型把PC和PSW保存到8字节区域；已有GNU RTI函数体恢复PSW/PC并将SP加8。原厂入口
及6003883a的RTI布局与此一致。因此本轮记录的**单次已知部分**为8+56+40=104。
GNU模型的中断控制器地址并非E-P7寄存器资格证据，不把模型当成相机执行。

## 仍不能合成完整任务上界的原因

- **特殊寄存器保存/恢复**：60030107/6003011c含UDF12/13/15/20/21。本轮只计显式
  SP操作，没有运行或独立证明这些扩展指令的全部硬件效应。
- **任务异常回调**：60038822仍可在任务栈上进入6003436e及TCB+52 handler。
  TCB+48为1时会跳过，但bootstrap现场资格尚未建立。
- **嵌套窗口**：6003881e在异常callback之前恢复原PSW。不能在该窗口未审完时，
  把“单次104”乘一个随意选择的中断层数，或直接与416相加后宣称总峰值520。
- **故障路径**：BREAK/NMI/debug及自有quarantine不是本报告的常规IRQ路径；原厂
  60030008会转入诊断代码60055250，其中继续调用其他服务。quarantine仍保持原有
  BREAK循环，本节点没有悄悄修改其失败行为。

下一项集中处理bootstrap现场TCB+48的资格和自有终止体的异常依赖；不为计算方便
默认关闭任务异常、不修改原厂IRQ handler，也不扩大栈配置掩盖未知量。
