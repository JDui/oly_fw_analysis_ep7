# Self-authored freestanding memory operations

`memory.c` implements byte-loop `memcpy` and `memset`, authored for this work without copying vendor/libc/GPL implementation source. The only included header is compiler-provided `<stddef.h>`. No native firmware routine/address is bound.

Semantics: return the original destination; copy exactly count bytes from source for memcpy, or write `(unsigned char)value` for memset. Zero count performs no loads/stores. Callers must provide valid, accessible source/destination objects for the requested count, including valid pointers for zero-count tests. memcpy's ranges must not overlap; this is not memmove. No MMIO/volatile, atomicity, synchronization, DMA or cache-coherence behavior is claimed. Ordinary C pointer/lifetime preconditions still apply.

Build flags include strict C11 `-O2 -Wall -Wextra -Werror -pedantic -fno-builtin -fno-tree-loop-distribute-patterns`. Target additionally uses `-ffreestanding`. Disabling builtin/pattern rewriting prevents the compiler from replacing these loops with calls back to the very routines being implemented. Future compiler/flag changes require rerunning symbol/instruction checks.

Host tests compile definitions and declarations with `-Dmemcpy=ep7_test_memcpy -Dmemset=ep7_test_memset`; libc and sanitizer interceptors retain their normal symbols. 19,608 cases cover zero through128 bytes, source/destination byte offsets0..7, exact return pointers, unchanged source and all surrounding canaries, and fill values including negative, >255, INT_MIN and INT_MAX. Strict and ASan/UBSan fail-fast runs pass. LeakSanitizer is explicitly disabled because this environment's ptrace prevents its startup; no dynamic allocation occurs in the test. An initial runner without that option failed at LeakSanitizer startup, then was corrected; this was not a target failure.

`check_memory.py` first verifies all local compiler/tool hashes against `prototypes/ep7_volatile_hl/target/build-manifest.json`. It executes only the self-authored host test. Target GNU GCC13.4.0 mn10300-elf compiles C to assembly, trusted gas produces an **unlinked** elf32-mn10300 object, and objdump verifies no undefined symbols. Assembly contains no call/calls/jsr instructions, hence no recursive call or dependence on native memcpy/memset. Both loops compile into byte loads/stores and conditional local branches. `_memcpy` and `_memset` use this GCC's ordinary C calling convention, so they can satisfy references from the same toolchain's portable core; this is NOT a firmware-native calling convention assertion.

Assembly and object outputs exist only in a cleaned temporary directory; metadata report is written by the caller. No target code linked or executed, no stock firmware input used, no camera memory accessed, no patch/image/installation generated. Parent must independently review before integrating the source into the portable prototype. Reproduce with `python prototypes/ep7_volatile_hl/target/check_memory.py`.
