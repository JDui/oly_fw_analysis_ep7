# E-P7 1100 单帧 DR 的 Auto ISO 与曝光锁定

2026-11-08 更正：用户要求 JPEG 高光映射优化，当前方案不再改动 Auto ISO 或 AEL。
以下约束求解／曝光版本研究保留为旧增益路线的证据，不是当前待实现功能。
当前方案见[实现记录](../../docs/ep7/SINGLE_FRAME_DR_IMPLEMENTATION.md)。

原厂解码主映像的运行基址为 `0x60020020`。本页核对的是曝光求解器使用的实际约束和锁定读取。当前固定 ISO 候选仍按原有准入运行。

## 原厂求解约束

`60427689 → 6042777c` 构造本次求解的 `EXP_MODE` 和 `EXP_SET`。`60429519` 读取 `0x810a`。普通分支把零传入 `EXP_SET+2` 表示 Auto，非零传入固定 Sv Q8。`60427991/604279a8` 分别读取 `0x949a` 和 `0x9a9a`，在 `60427998/604279af` 存为 `EXP_MODE+24/+26`。对应原厂 `613ed407/613ed418` 诊断为 `iso_limiter`、`iso_standard`。

`60427733 → 603f38f8 → 603fbe7a` 进入求解。`603fc14a` 调用 `603fc6ba` 为当前调用栈生成 44B 约束记录。`603fca0a` 按约束 `+42` 场景号，从 `60541326` 开始查找 70B ROM 行，行尾 `+68` 是场景号。已核对 3、4、5、6 等行的下列字段。

| 字段 | 原厂生产者 | 普通分支来源 |
| --- | --- | --- |
| Sv 上限 `+16` | `603fc785 → 603fc9c4`，`603fc792` 写入 | ROM 行 `+20` 的 `0x9f00` 由 `603fcaf1` 解为 `EXP_MODE+24`。属性零值时走原厂默认上限 `3328`。 |
| Sv 下限 `+22` | `603fc7a1 → 603fc9ed`，`603fc7aa` 写入 | ROM 行 `+40` 的 `0xa200` 解为 `1280`。`603fe808` 根据 `EXP_MODE+57/+58` 识别的另一配置取 `1536`。 |
| 默认 Sv | `603fcaf1` 的 `0xa000` 分支 `603fcb3f–4c` | `EXP_MODE+26`，属性零值时采用原厂默认。`0xa100` 也读取同一值并保留其专用判断。 |

`603fcaf1` 先看 `EXP_SET+2`。非零时跳到 `603fcb74`，用固定 Sv 参与原厂范围约束。Auto 路径继续解析上述 ROM 值，并在 `603fcbb6` 走原厂有符号限制。`603fc7ec–603fc971` 多处使用下限构造其他约束。候选应在 `603fc7a1` 的原厂下限返回后、`603fc7aa` 写入前决定是否提高下限，保留原上限、默认 ISO、EV 属性和原厂后续推导。等 `603fc6ba` 返回再只补写 `+22`，会留下按旧下限计算的关联值。最终求解中，普通 `603fd4e8` 在 `603fd4fe` 读下限；`603fcf68`、`603fe602–613` 等具体分支将上下限交给原厂夹限 `60420bee`。

已用原厂 ROM 行 `605413b2` 和严格 MN103 跑 `603fc9ed`、`603fc9c4`，仅为内部读的 `0xc222` 提供 0。普通 Auto 下限返回 `1280`，另一配置返回 `1536`；上限分别保留请求 `2048` 和 `1707`；固定输入 `1792` 返回 `1792`。本测试执行原厂解析和夹限，只覆盖计算输入，夹具提供 `EXP_MODE`、`EXP_SET` 和属性服务返回值。

## AEL 和逐拍绑定

`6041fd44` 由 `603f34e3` 调用，引用原厂诊断 `exp_through_change_ael_request`。它在 `0x622a04ec` 设请求状态 1 或 2，并复制 128B 输入到 `0x622a04f0`。`6041fb7d`、`6041fbf8` 的诊断分别标为 UNLOCK、LOCK。`6041fd32` 和 `6041fd3b` 分别读取状态 `0x622a04e8`、`0x622a04ec`。

即使设置了当前调用的下限，`603fc163` 仍能通过 `6040b4a7(0x100)` 判断锁定。该函数读原厂属性 `0xb664` 的 `0x100` 位。锁定分支 `603fc171 → 6040b586` 从 `0xb674` 索引 6、7、8 读取原厂锁定三元组，并在 `603fc178–603fc18d` 写进结果，绕过 `603fce91`。其中索引 7 进入结果 `+8` Sv。AEL 请求状态和求解器实际锁定属性各有自己的生命周期，单读请求状态无法证明当前结果的来源。

普通 `6042805e` 分别发布 Tv、Sv、Av，`604280fb` 将结果 `+8` 写到 `0xa04a`。`60427761–60427774` 随后把本次完整的 76B 结果复制到 `0x622a0714`。捕获在 `602ab693/602ab6a6/602ab6b9` 分三次读 `0xa02a/0xa04a/0xa03a` 填命令的 96B 元数据。`6029c759` 在原厂状态入口清当前命令，`6029c78f` 随后可触发 `6028e684 → 6042754a`；普通命令在后面的 `6029c997` 才发布。因此至少一条曝光计算发生在捕获命令创建之前。把早期求解通过全局当前命令裸地址绑定，会错过这条边。数值相同也无法证明三项取自同一次 AE 或同一次 AEL。

待验证的接合点是已提交的设置版本、AE 求解／AEL 锁定版本以及后续捕获所有权。求解时先获取可传递的设置版本和本次计算标识，再由真实曝光发布与锁定生产者将标识传给捕获；使用已锁定曝光时沿用锁定时绑定的档位。若当前有效上限低于下限、锁定版本无法追认或某个原厂范围结果无法用于已证明的下游增益和 JPEG 路径，整个 HDR 方案须在原厂曝光被采纳前撤回。只在 `6029d68e` 或成片阶段回退，会留下已经改变的 Tv 或 Av。

固定 ISO 候选只验证了名义 Sv Q8 `1792`、`2048`。Auto 求解还能产生档间值和更高值，而默认 STILL 校准表与较高档的数字残差、范围切换仍需联合验证。现阶段已有可复查的原厂下限入口和 AEL 旁路。完整设置版本、锁定写入与捕获绑定尚待验证，Auto ISO 接线维持研究状态。
