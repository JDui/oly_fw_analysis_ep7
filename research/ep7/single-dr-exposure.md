## 采集计算与物理增益边界

- `601e77c0` 只清除 168 字节命令并保留首半字。在 `601e77d8`，首半字为 7 时查 ROM 分派表（`601ecc7c`），跳往 `601e785a → 6011f863`。后一函数读取命令 `+4` 的曝光结构，使用结构 `+6/+8` 打包日志事件 354，使用 `+10` 打包日志事件 355。原厂 `cam exp` 的输入解析 `613cdef6` 对相同三个半字写入并逐项打印 Tv/Sv/Av，见 `613cdfcb/dfd6/dfe0` 与 `613ce003/ce018/ce02d`。命令结构的偏移与上表标签结构独立。
- `6011f9ed → 6012101b` 处理有 `+60` 指针的命令。`6011fa45 → 6011fa59` 是其中无 `+60` 指针、无特殊先决条件的一条路径，后续调用 `6014f5e0`（`6011fac6`）和 `60600389`（`6011fb27`）。控制器也在 `602a5624` 和 `602a5c06` 进入命令分派。不同入口、状态和命令生命周期需分别核对。
- `6012e654` 的 `6012e69c–e6d3` 读取曝光结构 `+8`，视标志 0x400 决定是否加补偿值，按模式描述符 `+68/+70` 作有符号上、下限约束，写工作结构 `+46`。随后 `6012e6db` 把原 `+8` 回显到曝光结构 `+50`，`e6f0/e6f7/e6fe` 选表、取区间并算校准值。`6012ed9e` 也读取曝光结构 `+8`（或工作 `+108`），并对 `+110` 的加和与 `+112` 的独立值执行两次相同的描述符限制，然后在 `6012ee10/ee18/ee20` 进入同一套查表函数。
- `6012f788` 从命令 `+4` 按模式选表，`6012f760` 取 ROM Sv 采样点，`6012f32e` 将工作结构 `+46` 映射到校准值。`6012f3c0` 把剩余校准分量转换为请求 `+44` 的乘数，分量为零时写 `65536`。`6012f401` 将低增益范围标志写入请求 `+48`，`6012f474` 把两路增益码写入 `+56/+60`。二者的下游与 `+44` 分开。参见[校准研究](single-dr-calibration.md)。

## 普通静态拍摄请求到 TG_GAIN

1. 原厂 `6014c4ae–ba` 用格式 `STILL = %d` 打印模式 10，相邻分支分别打印 `STILL_LQ = 11` 和 `STILL_HS = 18`。`6012d3b8` 的模式切换诊断也以 10 为 `STILL`。上层 `CAM_SENSOR_MODE_*` 有独立编号。
2. [既有原厂构造器仿真](../../docs/ep7/CANDIDATE_SELECTED_PARAMETERS_SIM.md) 在场景 inactive、普通 class `0x10000` 的 fixture 中从原生调用点 `6029d09c` 执行 `602a6583`，得到首字为 10 的描述符 `6223d488`。`6029d3c4–ca` 将它放入 engine `+12`，相邻 `6029d3be` 将 engine `+4` 初始设为 NULL。后续 `6029d5d7–da` 将同一当前拍摄命令 `+60` 的 96B 曝光记录挂到 engine `+4`，`6029d688/68e` 提交 engine。`6029f847–850` 在另一提交路径写入同一指针，`6029f91f → 602aa5ba` 从该请求取拍摄 ID 和缓冲资源。上层 TOP 的 `60120dcb–dd2` 让下层包 `+8` 指向 `&engine->+4`。`6014e74d/757` 从该包继续解引用并检查模式 10/11。`6014dd6a` 另从 `6014212e` 当前已初始化的模式描述符复制字段。
3. 下层入口 `6014dd11` 依据 `60142151` 的模式切换结果选择配置 selector。selector 7 在 `6014e533` 构造 type 8 请求，`6014e58e` 保存同一 `&engine->+4` 指针，`60141ff8` 通过 ROM `601c9a88` 的 selector 7 进入 `6013cc9d`。对非空输入，`6013cccc` 经 ROM `601c9a20` 调用 `601426b8`。它把 56B 的原模式描述符复制到工作区，并在 `60142705` 将指针放入配置上下文 `+20`。当 engine `+4` 非空时，它也把 92B 原曝光记录复制到工作区，并在 `60142758` 将指针放入配置上下文 `+12`。`6013cce0 → 601428c8` 从这两个指针形成 type 0 请求的 `+4` 模式和 `+20` 曝光记录指针，`601429cc → 6012e2fc → 6012e654` 执行原厂计算。原厂模式 10 描述符 `601ca690` 的 `+68/+70` 是 Sv 输入范围 3033/1024。
4. 同一 selector 7 继续到 `6013cd94 → 6013fe45 → 6013c2ef`。原厂置前端配置 `+0` 的 bit25，把 type 0 请求 `+48/+56/+60` 的低 16 位零扩展为 32 位，存于 `*(前端配置+472)` 的 `+0/+4/+8`（`6013c332/337/33e`）。`601503f3–60150403` 把此 24B 数据块挂到作业表 `+1800` 所在作业的 `+20`。`6014f430` 用 bit25 激活该作业的 `+68`，与 `613d63c7` 的原厂 `tg_gain` 字段一致。第二个 `tg_gain2` 是相邻作业，有自己的 `+24` 数据指针和 bit26。
5. `601380da → 60138125 → 601381b6` 的 type 7 分支在 `601382a0–bd` 把整个 24B `TG_GAIN` 数据块复制到当前 TG 槽并置 bit16。`60138c8b–60138cc1` 消费 bit16，并在 `60138cb5` 调用 `6013a30e`，将 A/B 码各拆成低八位和高四位，填入 `0x621f5584/558c/5594/559c` 的 `[23:16]`，标志写到 `0x621f557c` 的同一字节位。`0x621f56a4/56a8` 保留完整增益码。ROM `601bad04` 描述六个 8B 串行记录，起始指针为 `621f5570`，因此包括这些数据字。`6013bc71 → 6014d5a3` 可提交包含该描述符的列表，尚需确认普通静态拍摄实际选中的列表和同步边沿。物理应用时刻、传感器转换增益和饱和值仍需真机验证。

## 捕获结果与元数据

`6029cd4f → 602a7556` 领取 96B 槽，在 `6029cd5c` 保存到当前命令 `+60`。`6029cd89 → 602ab5e4` 初始化该槽，普通 class `0x10000` 族读取 `0xa02a`、`0xa04a`、`0xa03a`，分别写入 `+6` Tv、`+8` Sv、`+10` Av（`602ab693/6a6/6b9`）。`6029d4f6` 和 `6029f78b` 均从 `0x6223d414` 取当前命令，随后将此 `+60` 指针交给 engine `+4`。下层 type 0 计算在 `6012e6db/e6e3/e6ec` 将输入回显到 `+50/+52/+48`，`601429ec/fd/60142a0e` 经请求的原嵌套指针写回该槽。

`602a281a` 收到 event `0x4b` 时从同一当前命令全局 `0x6223d414` 取命令（`602a2822`），在 `602a283c` 传给 `602a91ee`。后者取命令 `+60`（`602a920f`），从其 `+50/+48/+52` 读取 Sv/Tv/Av，映射为捕获记录的 `+24188/+24182/+24192`，同时发布属性 `0x1eda/0x1eba/0x1eca`（`602a9300/9310/9322`）。因此普通分支有一条可定位的原厂生产者链，仍需补做从实际提交到对应事件的严格生命周期复现，含异常和其他 selector 的行为。此前仿真在 metadata `+50` 尚未执行该生产者时严格停止。

类型 11 命令有更早的 capture ID。`602987ed` 调用 `6029b4e7` 分配，`602987f3` 写入命令 `+0`，`60298806` 把同一命令指针放进控制器事件。`60289dac` 从事件 `+12` 取命令，并清除其 `+60/+64/+68`，保留原 `+0`，再由 `6029c997` 发布。另一分支可在 `6029cdd0 → 602a3116` 为同一命令预先重新分配 capture ID。

普通单拍还有一条不经过 `0x4b` 的 `StlTake` 路径。`6029d8e5–6029d91c` 在 `0x6223dbf4=0`、`0x6223dd48!=1`、`0x6223dabc=0` 时选择状态 14。ROM `6042d688–6042d698` 将其标为 `StlTake`，入口 `6029d97c`。该入口在 `6029d9db` 注册 `6029e956`，后者在 `6029e966` 调用 `602a91ee`，此时节点参数为零。原厂在控制器 `+2348=0` 且 `+1696!=5` 时直接读取当前命令 `+0` 的 ID（`602a9206`）。结果调用返回后 `6029e97e` 发出阶段位 `0x800000`。同一状态的 `6029e988` 使用包含该位的掩码 `0x800424` 注册（`6029dbae–6029dbbd`），可经 `602a4d0c/602a4d34` 进入事件 55。状态 14、19、20 的事件 55 映射 `602a3a6e`，由 `602a3a84` 通知阶段状态。`6029dabe` 注册的 `6029e99f` 执行 `6029e9ae → 602a4ffe → 602a4db4`，`602a4fe5` 将该命令交给 kind19 的上游。状态 33 的 `602a283c` 和状态 14 的 `6029e966` 各自有明确的原厂所有权。

RAW/EXIF 侧的 `IsoSpeedRatings` 诊断 `613f8ffc–9012` 打印元数据半字 `+128`。另一个任务记录的 `GainAdj` 和 `SvAdj` 诊断 `603e5bee–5c0a` 分别读取其 `+276` 和有符号 `+278`。两处字段属于不同记录，尚缺将其与本次采集命令及实际 ORF 字段对应的证据。仅修改诊断或写入 ISO 元数据不会改变采集。

## 已定位的时序边界

HDR 冻结必须早于 `6012e69c` 读取曝光并在 `6012e6ef` 进入采集增益计算，且曝光与成像须使用同一捕获快照。当前 HSL 的选择点和 `602a91ee` 都属于后置阶段。标签构造器提供名义、模拟、数字 Sv 可分别表达的证据。仍需把普通单拍命令中的曝光结构 `+8` 向上接回 AE 和曝光锁存，追踪 TG 命令提交和生效时刻，并证明普通单拍、机械／电子快门和实时取景各自的模式校准边界。

原厂 Auto ISO 下限和 AEL 旁路另见 [Auto ISO 与曝光锁定](single-dr-auto-iso.md)。
