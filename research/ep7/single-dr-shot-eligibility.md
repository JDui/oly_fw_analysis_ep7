# E-P7 1100 普通单拍的 HDR 前置资格

2026-11-08。以原厂 decoded main `generated/ep7/full-input/main.decoded.bin`、CPU 基址 `0x60020020` 作局部反汇编和 ROM 表读取。以下是可供接线的证据及边界。未运行完整拍摄、验证实机或改动生产挂点。

## 固定 ISO

公共属性映射 `0x604d6c14 + 6*4` 为 `0x810a, 0`。ID 6 的两份 ROM descriptor `0x604cd6ac`、`0x604cd6c0` 分别用原始半字表 `0x604cacfc`、`0x604cad2c` 和公共 32 位值表 `0x604aeddc`、`0x604aee3c`。两表的正 Sv 分支一致。

| `0x810a` 原始值 | 公共值 | 用法 |
| ---: | ---: | --- |
| 0 | 0 | Auto。 |
| 1280 | 2 | 低档的特殊公共值。2 不是 ISO 数值。 |
| 1536 | 200 | 普通固定 ISO200。 |
| 1792 | 400 | 普通固定 ISO400。 |
| 2048 | 800 | 普通固定 ISO800。 |

部分普通 ISO 另有负编码映射。首个实验可严格只允许正的普通编码，且要求 `metadata+8` 的名义 Sv 与该值完全相等。AE 的 `0x60429519` 读 `0x810a`，为零时另有条件替代值。下游 `0x602a7eb0–0x602a7ecf` 的捕获记录在零时把 `+24008` 写成 1280，因此该字段不能区分 Auto 和固定 ISO。`0x602ab696–0x602ab6a6` 从 `0xa04a` 写入提交前 96B 曝光记录的 `+8`。

若初版保持采集策略的普通 ISO200 地板，取 Q8=1536。则 200／400 的名义门槛分别为 Q8=1792／2048，对应 ISO400／800。TG 标定在低于该值时也可计算其他控制字。实装模拟增益与饱和表见[校准证据](single-dr-calibration.md)。

## 记录格式

- 公共属性 `0x604d6c14 + 10*4` 为 `0x8141, 0`。原厂 `0x6030371d–0x60303733` 以 `PRM_MODE_QUALITY` 打印同一原始属性。尺寸与压缩是另外两项。`0x60303738–0x6030375f` 使用画质模式索引 `0x8161`，`0x602a7f20` 也按模式索引 `0x8151`。
- 捕获 populate `0x602a7ee7–0x602a7efd` 把原始画质复制到 capture+24012。`0x602a7f2d–0x602a7f73` 将画质 4 转为 capture+23920=2，并清零 JPEG 尺寸字段 +24028。画质 3 转为 +23920=1 并保留尺寸。其余经 `0x8231` 决定 +23920=5 的特殊路径或普通 +23920=0。
- 原厂文件头 `0x60300083–0x6030009f` 为 +23920=0／1 写 TIFF/Exif magic 42，为 +23920=2 写 ORF 的 `0x4f52`。由 ORF magic 和主动清零 JPEG 尺寸可确认画质 4 为 RAW-only。画质 3 和普通 JPEG 都有原生 JPEG 参数。画质 3 的正式 ORF 保存链未在这次审查回放。
- `0x602a7f73–0x602a7fff` 在 `0x52b1` 等于 2／3 时准备另一组画质、尺寸及压缩。原厂读取者 `0x6061f112–0x6061f149` 在相同条件下才按另一 selector 取 +23922，否则读 +23920。首轮只接主配方，显式拒绝该分支和 `0x8231` 的特殊格式。提交前可取得这些原始属性。+23920 在提交后的 populate 才生成。

普通 JPEG 的最窄初始值可限定 `0x8141=1`，该值也是原厂模式初始化证据的有效画质值。扩大范围前仍需核对其余普通值及媒体策略。即使画质读两遍相等，仍未排除原厂在 `0x6029d68e` 提交后和 `0x6029d7cd` populate 前读到新设置。接入采集增益前须闭合格式冻结或原厂设置排他。下游才发现 RAW-only 时已不能撤回本次曝光。

## 原生控制器的单拍与快门条件

| 字段 | 原厂证据 | 可供初版使用的限制 |
| --- | --- | --- |
| 继续拍摄模式 `0x6223dabc` | `0x602a76ff–0x602a770b` 以 `continue_mode` 输出。Standby 入口 `0x6029c6c3` 的 `0x6029c723–0x6029c726` 从同一进入拍摄状态的 payload+9 搬入。`0x602a5e09` 把值 0／1 映射成不带 continuation flags，2→4、3／4→2。前置提交点 `0x6029d580–0x6029d587` 把此结果写入子配置+16。 | 严格要求 `0x6223dabc=0`，即首个原厂非继续拍摄候选。只检查子配置+16=0 会同时放行原始值 1。 |
| 控制器快门模式 `0x6223dbea` | `0x602a77bd–0x602a77c9` 以 `shutter_mode` 输出。`0x602a471d` 的 mode 11／18 分支在 `0x602a47a7–0x602a47fb` 写 owner `0x6223d41c+1998`。电子／特殊标志或 `0xf101=1` 可选 2，另一个 `0x99e1=1` 分支选 1，普通分支选 0。`0x6029d0b0`、`0x6029cbe3` 已在提交前使用此值。 | 只考虑 0，同时检查所属普通命令、描述符、请求状态。一个提前比较 `owner+1664==2` 也可令该字节为零，单查零无法证明是普通机械拍摄。 |
| 模式与身份 | `0x6029d3c4–0x6029d3ca` 让普通 engine 的 +12 指向 `0x6223d488`，其 mode 10 为原厂 `STILL`。`0x6029d5d7–0x6029d5da`、`0x6029f847–0x6029f850` 都绑定当前 command+60，后续提交语义分别为 StlRdy2 和 StlLiveTake。 | 先只支持已审查的 StlRdy2 普通 mode 10 分支。传感器模式 10 不能独立判定快门或连拍。StlLiveTake 写同一全局，仍需独立准入。 |

命令有效驱动标志的生产链、模式 0 何时落到完整机械快门命令、自拍／闪光／包围等所有组合的排除还未逐条闭合。以上状态字可用于缩小正常路径。

## 第三页设置接线

1. 复用[原生曲线探针](single-dr-curve-ui.md)的 owner 检查。以 child+216 的已确认 ROM 行获得 scope，再核对 native 公共属性 111。第一批仅可让 `ep7dr_stage_level(public_mode, level)` 处理 Natural=1 及 COLOR=54／55／56／64。普通共享 ROM 行不能单独把其他图像模式认作 Natural。
2. 从同一设置模块读取当前档位后才计算增减。当前 API 只有 setter，可补一个返回 0–2／拒绝状态的只读 getter。HDR INFO hash `0x61159e74` 只切子页。双拨轮在 `0x61159ee4`／`0x61159ee8` 仅为已通过 gate 的 HDR 页调用 stage。长按复位在 `0x61159e44` 调 stage OFF。C ABI 传 D0=public_mode、D1=level，使用各原生位置的帧保护 veneer。只有成功写入且值变化才更新显示。第三页触控隔离和原厂输出发布继续复用验证过的挂点。
3. stage 当前使用 core 0 的对齐 32 位暂存值。`0x8050` 非零时返回失败。动态 GUI task 由 `0x60cfceba` 构造并继承创建者 domain。GUI 的创建者 core 尚未证明。应核对实际 task/TCB 和域，或实现明确的跨域访问。GUI 镜像、另一个 cached alias 或 UI 事件结果无法代替同一 staged 值。 [GUI task domain](../../docs/ep7/TASK_DOMAINS.md)
4. 额外页保留原生 +222 和属性 1088。重建清理额外页后恢复高光／阴影入口。渲染从 staging getter 呈现所选档位。提交前的有效档位由 capture gate 独立决定。UI 尚缺可展示的不可用原因，stage 成功只代表所选档位已更新。

复查使用现有工具链的 `mn10300-elf-objdump -D -b binary -m mn10300 --adjust-vma=0x60020020`，按上述起止地址查看。表项为小端，公开 ISO raw 表每项两字节，public 映射每项四字节。未做 SHA 校验或运行额外测试。
