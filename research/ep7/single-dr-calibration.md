# E-P7 1100 采集增益标定与饱和参数

## 证据范围

输入为 `generated/ep7/full-input/main.decoded.bin`，CPU 基址 `0x60020020`。该输入来自现有五组件结构检查，见 `research/ep7/full-input-structure.json`。此轮用现有 Docker volume 内 GNU Binutils 2.45 反汇编局部窗口，并按小端读 ROM 表和字符串。未执行 SHA、相机、服务校准或 flash 操作。

## 固件取数与加工

| 证据 | 结论 |
| --- | --- |
| `60f135a7`、`60f13649` | 原厂参数描述把 `0x712a` 命名为 `PRM_CCD_DBGAIN_STANDARD`（24 项，FLASH），把 `0x7192` 命名为 `PRM_CCD_SATURATION_LEVEL`（23 项，FLASH）。`60091a88` 找到实际 ROM `0x712a` 默认记录，头为两个半字 `0x712a,24`，后接 24 个有符号半字。默认值与各机身 FLASH 实际标定分开。`600be024` 也有 `0x7192,23` 头，但未验证其后为连续 23 项默认标定，未从那里取数。 |
| `6012e2c8–6012e2f2` | 按编号调用 `6005e947`，返回地址分别存入 `0x621f3ff4`（dB gain）和 `0xa272c060`（saturation）。同一初始化还读取 `0x703a` 至 `0x621f3ff8`，原厂名为 `PRM_CCD_SUBTRACT_OB_LEVEL`。 |
| `6005e947 → 6005d924 → 6005c8cf` | 地址来自已初始化的参数描述表。`6005d924` 用 ID 右移四位索引，每项 8 字节，按条件先查 `0xa2707a88`，其次 `0xa26ffa88`。读取描述 `+4` 后经间接地址转换；查不到返回零。该路径给出了可直接读取实际标定的入口。 |
| `60c169a1–60c169c8`、`60c17010–60c17048`、`60c17bc2–60c17bd9`、`60c18d83–60c18da4` | 独立服务校准对 `0x712a` 操作 24 个值，工作对象来自 `0x62334ee8`，gain 数组从 `+266` 开始，元素为有符号半字。服务代码读取/计算值并输出 dB、Sv、饱和差等信息。此域不可作为逐帧写入口。 |
| `6012e6f0–6012e703`、`6012ee10–6012ee25` | 两处调用同一 `6012f788 → 6012f760 → 6012f32e` 序列。`6012f788` 按输入 `+4` 的 0…11 分支，选择 `0x621f3ff4` 的不同子表、对应 ROM Sv 表及原生光学黑电平参数。 |
| `6012f760–6012f785`、`6012f311–6012f32b`、`6012f32e–6012f3bd` | 以 Sv 选择区间，取相邻 dB 标定半字；普通路径按 Sv 差值插值，另一分支从原生上下文 `+72/+74` 的界限和比例常数 1541 推算下一个 dB 值。该路径计算标定增益，不能以线性移位直接改其输出。 |
| `6012e31e–6012e328 → 6014c33d–6014c366` | 用命令 `+4` 的 32-bit mode 从 ROM `601ca398` 查 12 条、每条 76 字节的配置。`6014c4ae–6014c4ba` 的同域诊断将 10 标为 `STILL`，邻项分别把 11/18 标为 `STILL_LQ`/`STILL_HS`。这组枚举与上层 `CAM_SENSOR_MODE_STILL(10fps)=7` 有别。 |
| `6012e6b4–6012e6d3`、`6012edd0–6012ede9` | 增益计算前把 Sv 夹在模式配置 `+68/+70` 的有符号上下限之间。`STILL` 行 `601ca690` 的两个字段为 `3033/1024`，其独立标定输入阈值 `601ba39c` 为 `1024,1280,1536,1792,2048,2304`（`6012fa63–6012fa76`）。这证明普通 `STILL` 求值器的输入下限为 4.0 Sv。实际模拟增益还受 `0x712a` 标定、下游变换和传感器控制约束。 |
| `6012f3c0–6012f3fe` 与 `6012f474–6012f4c3` | 标定结果下游有两条不同变换。前者零输入给出 `65536`，非零经过 `6011c5e9` 和移位；后者通过同一变换生成互补控制值写入对象 `+56/+60`，控制值上限 3839，超出部分另存。写入传感器/ISP 的物理意义还需跟进消费方。 |
| `60143750 → 6012ff40` | 当 mode 参数等于 10 时，按 `601ba4b4` 的 23 个 Sv 阈值从 `0xa272c060` 指向的实际饱和表取值。其他 mode 返回零。这是有别于 dB gain 和标称 ISO 的第三套数据。 |

`601ba4b4` 的 23 个原厂阈值为 `1149, 1280, 1365, 1450, 1536, 1621, 1706, 1792, 1877, 1962, 2048, 2133, 2218, 2304, 2389, 2474, 2560, 2645, 2730, 2816, 2901, 2986, 3072`。与 Q8 Sv 相符。作为对照，`601cdd70` 开头含 `200,250,320,400,500,640,800,1000,1280`。这些表分别用于阈值和标称值，不能互换。

## 原厂 STILL 算术回放

统一的 [`single-dr-exposure-probe.py`](single-dr-exposure-probe.py) 使用原厂 `601ca690` 模式描述符、`60091a88` 的 dB gain 默认记录和 `60091638` 的光学黑默认记录。它在严格 MN103 下执行原厂 `6012e6ef–6012e76d`，包括 dB gain 选表、区间和插值、工作对象拷贝、上下限及两个独立控制结果。命令类型、模式指针、gain 校准指针和待求值的 Sv 是显式 fixture，替换的 Sv 在原厂 AE 结果装载和回显之后写入工作对象。完整快门控制和物理硬件提交未执行。

| 输入 Sv Q8 | dB 标定 Q16 | 命令 `+48` | 命令 `+56/+60` | 命令 `+44` Q16 |
| ---: | ---: | ---: | ---: | ---: |
| 1024 | −394496 | 81 | 0 / 0 | 65536 |
| 1280 | 0 | 1 | 0 / 0 | 65536 |
| 1536 | 394496 | 1 | 2046 / 2046 | 65536 |
| 1792 | 788992 | 1 | 3070 / 3070 | 65536 |
| 2048 | 1183488 | 1 | 3583 / 3583 | 65536 |

五个输入均正常返回且 SP 恢复。Sv6/7/8 的两个控制值对应 `4095/(4095−code)` 约 2/4/8 的编码关系，独立的 Q16 乘数保持 1.0。Sv4 与 Sv5 产生相同控制值但不同标志，仍需用消费方解析标志 81 的物理语义。结果确认了 **原厂控制字** 与 **独立乘数** 的数值分离。实际 AE 命令与标称 ISO 对应、实机 FLASH 和传感器下游保留为单独证据。

复现命令和各阶段指令数见[曝光探针记录](single-dr-exposure.md)。

## TG_GAIN 下游

- `6013c2ef` 将校准命令 `+48/+56/+60/+64/+52` 写入 TG_GAIN 的 24 字节参数区。`601503f3–60150406` 建立 job type 7，并让 job `+20` 指向同一 TG 参数区。`6014f430` 更新 config `+1868` 的使能字节，由 `613d63bd–613d63cd` 原生诊断命名为 `tg_gain`。相邻 `tg_gain2` 有自己的 job 指针及使能。
- `60131137/6013113e → 601380da` 分派 type 7，表 `601baad0` 的 key 1 对应 `60138125 → 601381b6`。`601382a0–601382b8` 将 job `+20` 的完整 24 字节复制至 TG 工作槽，并置 pending bit 16。`60138c8b–60138cc2` 消费 pending 并调用 `6013a30e`。
- `6013a30e` 把 TG 标志写进 `0x621f557c[23:16]`。两个控制字各自拆成低 8 位与高 4 位，分别写进 `0x621f5584/0x621f558c`、`0x621f5594/0x621f559c` 的同一字节 lane。`6013a44c/6013a453` 留存两份未拆控制字。低 8／高 4 的目标 lane 在严格 MN103 回放中按五组输入实际变化，其他位保持原值。`6013c302/6013c348` 把曝光记录 `+24` 传到 TG 数据块 `+20`，之后 `60138ca3` 读取该字进入 TG 状态；该字段即使初始为零也有原厂语义。
- ROM `601bad04` 描述符为 `{count=6, pointer=621f5570, reserved=0}`，覆盖 6 个 8 字节串行记录，包含上述所有 lane。初始化后的实际选择列表包含该描述符，例如 `61f99c38`（ROM `60231ef8`）的 `+8`。`6013bc71` 遍历选择列表，经 `6014d5a3 → 6011bb99` 交给队列。哪些序列触发具体列表、实际总线写入及硬件标志 81 的含义仍需单独验证。

## 机身标定与公开 RAW 数据

官方 E-P7 规格确认正常标称设置为 ISO200 起，扩展到 ISO100，ORF 为 12-bit 无损压缩。服务诊断 `60c18b9f` 也引用 `ISO100`，标定消息同时讨论 `Sv5`，但这不足以把菜单 ISO 与命令中的有效模拟 Sv 按等式绑定。[OM SYSTEM E-P7 规格](https://jp.omsystem.com/product/dslr/pen/ep7/spec.html)

独立的 E-P7 RAW 实测可核对趋势。Photons to Photos 两图表的 E-P7_12 公开数据在 ISO100/200/400/800 的 `log₂(DN)` 为 `−0.38/−0.29/0.43/1.23`，折算电子读噪为 `2.25/2.35/2.07/1.87`。按 `2^log₂(DN) ÷ e⁻` 推得相对 ISO200 的转换增益约为 `0.98/1/1.87/3.61`。两图中的电子数含作者的换算模型，LOW100 又是扩展档。这组趋势支持 ISO200/400/800 值得作为首轮比较点，不能独立确定本固件写入的传感器寄存器、前端截断点、每种快门的基准增益或 HDR 的实际有效下限。[原始 DN 图表](https://www.photonstophotos.net/Charts/RN_ADU.htm#Olympus%20PEN%20E-P7_12) · [输入参照噪声图表](https://www.photonstophotos.net/Charts/RN_e.htm#Olympus%20PEN%20E-P7_12)

## 原厂 DR 字段的边界

`6040c4c9–6040c55a` 和 `6040c80f–6040c896` 中 `Drange/lv w/n/mov w/n/stl w/n/gain` 是受诊断条件控制的格式化输出。它们从 `603f396e → 60419f23 → 6040e57e` 返回的结构读取半字。`6040e57e` 按两个原厂属性选择其中一项 597/341，并设置另一项 295；不能从这几个数推出单帧保护倍率。`613df2bd–613df2ec` 另显示结果描述符 `+108/+110` 为 `DRangeInfo.BvRev/SdrRecord`。其后 `+112` 开始的 `ApicalInfo` 还有独立的亮度和直方图诊断。目前这些是曝光和测光证据，尚未接到在普通单帧输出上同时改变硬件增益与 gamma 的生产者。

## 重现

复用现有本地工具链。任意一段指令窗口可替换下方 `--start-address` 和 `--stop-address`。

```powershell
$ep7Root = (Get-Location).Path
docker run --rm --pull never --network none --mount "type=bind,source=$ep7Root,target=/repo,readonly" --mount 'type=volume,source=ep7-research-toolchain-20261030,target=/work,readonly' rust:1.96-bookworm /work/install/bin/mn10300-elf-objdump -b binary -m mn10300 -D -z --adjust-vma=0x60020020 --start-address=0x6012e2a8 --stop-address=0x6012e2fc /repo/generated/ep7/full-input/main.decoded.bin
```
